Distinguishing locate and gather semantics

Clarifying gather and locate naming conventions

Proposing renaming gather argument to locations

I would keep rray_gather(). Calling it rray_locate() would reverse the meaning established by rray_locate_min() and rray_locate_max().

These names imply a useful producer and consumer relationship:

locations <- rray_locate_max(x, axis = 2L)
values <- rray_slice_locations(x, locations, axis = 2L)

locate finds and returns locations. slice_locations and gather consume locations and return values.

With rray_locate() as the gather operation, this becomes confusing:

locations <- rray_locate_max(x, axis = 2L)
values <- rray_locate(x, locations, axes = 2L)

The first locate produces locations, while the second consumes them.

I like this division:

  • rray_locate_*() produces locations.
  • rray_slice_locations() consumes one location array tied to one axis.
  • rray_gather() consumes location arrays for any number of axes.
  • rray_slice_axis() consumes an ordinary R subscript.

I would consider renaming gather’s indices argument to locations:

rray_gather(x, locations, axes = NULL)

That would connect it to the locator functions without changing the meaning of the verb.
