The warning

Apple clang 17 raised -Wbitwise-instead-of-logical 7 times, in src/missing.h:16 and six places in src/equal.c:

const bool missing = rray_int_is_missing(x) | rray_int_is_missing(y);

Clang warns when | joins two bool function calls. With ||, the second call would be skipped whenever the first is true. With |, both always run, and clang assumes you meant ||.

The | is deliberate, and I measured that it matters. I compiled equal.c and compare.c both ways and counted the loops clang turned into SIMD code (processing several elements per instruction):

File Vectorized loops with | Vectorized loops with ||
equal.c 121 17
compare.c 141 33

So switching to || would have cost a lot of speed. I kept |.

The fix

The warning only fires when the operands are calls. Reading plain local variables doesn't trigger it, so I store each result in a local first:

const bool x_missing = rray_int_is_missing(x);
const bool y_missing = rray_int_is_missing(y);
const bool missing = x_missing | y_missing;

rray_cpl_is_missing() in missing.h got the same change, using real_missing and imaginary_missing.

I also changed the RRAY_COMPARE_ONE macro in src/compare.c. It uses the same pattern but doesn't warn today, because clang goes easier on code inside macros. I changed it so every missing-value check in the package is written the same way.

I chose this over casting one side to int (what clang itself suggests) because the locals read more plainly and need no cast.
