# Names and titles across several inputs

## Goal

When a function builds one result from several inputs, the inputs must agree
on names and titles. If they don't, the function errors instead of silently
picking one input's names.

```r
jan <- array(1:2, 2, dimnames = list(c("north", "south")))
feb <- array(3:4, 2, dimnames = list(c("south", "north")))

rray_stack(jan = jan, feb = feb, .axis = 2)
#> Error in `rray_stack()`:
#> ! Can't find common names at axis 1. `jan` and `feb` have different names at position 1: "north" and "south".
```

Today this succeeds, labels every row with the order of `jan`, and the `feb`
column is silently wrong.

There is no argument to choose another behavior. To resolve a conflict, remove
the names from one input with `rray_set_names()`, which returns a view and
does not copy the data.

At the same time, titles stop being dropped by these functions.

## Which functions keep names

A function that takes values and returns the same kind of value keeps names.
A function that returns a verdict about its inputs drops them.

- `rray_add()` takes numbers and returns numbers. The result is a new value at
  the same labeled position, so the names still describe it.

- `rray_and()` takes logicals and returns logicals. Two masks over rows `a`
  and `b` combine into a mask over rows `a` and `b`.

- `rray_equal()` takes anything and returns logicals. The result answers a
  question about how the inputs relate, so it is not labeled like either one.

The rule also decides what a name conflict means. Two masks with different
row names are misaligned, so `rray_and()` errors. Comparing two arrays whose
names differ is an ordinary question, so `rray_equal()` answers it.

`rray_if_else()` is left out of this rule and keeps dropping names.

## Functions in scope

| Function | Names | Titles |
|---|---|---|
| `rray_add()`, `rray_subtract()`, `rray_multiply()`, `rray_divide()`, `rray_exponentiate()` | Must agree | Must agree, kept |
| `rray_and()`, `rray_or()`, `rray_xor()` | Must agree | Must agree, kept |
| `rray_pmax()`, `rray_pmin()` | Must agree | Must agree, kept |
| `rray_combine()` | Must agree, except on `.axis` | Must agree, kept |
| `rray_stack()` | Must agree, new axis from the names of `...` | Must agree, kept, `""` on the new axis |
| `rray_broadcast()`, `rray_broadcast_common()` | One input at a time, never errors | Kept, including on broadcast axes |
| `rray_equal()`, `rray_not_equal()`, `rray_greater_than()`, `rray_greater_than_or_equal()`, `rray_less_than()`, `rray_less_than_or_equal()` | Dropped | Dropped |
| `rray_if_else()` | Already dropped, unchanged | Already dropped, unchanged |

## Names rules

For each axis of the result:

- An input has a say only if it has names on that axis and its dimension
  there is not broadcast. An axis of dimension 1 that stays 1 is not
  broadcast.

- An input that is missing the axis, because it has a lower dimensionality,
  has no say.

- Every input with a say must have exactly the same names. There are no
  holes: `c("r1", "")` and `c("r1", "r2")` disagree. `NA` agrees only with
  `NA`.

- If they agree, the result has those names. If no input has a say, the axis
  has no names.

- The combine axis of `rray_combine()` is not checked. Its names are pasted
  together from every input, with `""` for unnamed inputs, as today.

- The new axis of `rray_stack()` is not checked. Its names come from the names
  of `...`, as today.

## Titles rules

Titles are the names on the dimnames list.

- An empty title, or no titles at all, has no say.

- Every other title on an axis must agree, including titles from inputs that
  broadcast on that axis or have no names there. A title labels the axis, not
  its positions, so it survives broadcasting.

- Because all non-empty titles must agree, the title of an axis is that one
  agreed title, or `""` when nobody has one.

- The result has a titles vector exactly when some input has one.

- The combine axis of `rray_combine()` is checked like any other axis.

- The new axis of `rray_stack()` gets the title `""`.

- `rray_broadcast()` keeps every title of `x`, so it no longer depends on
  whether any broadcasting happened.

## Errors

Inputs are visited left to right, and the axes of each input left to right.
Names are checked before titles on each axis. The first disagreement errors.

The error names the first input that had a say on the axis and the first input
that disagrees with it. For names, it reports the first position that differs.
The wording mirrors the existing `Can't find common dimensions` error in
`src/dimensions.c`.

```text
Can't find common names at axis {axis}. {x_arg} and {y_arg} have different names at position {position}: "{x_name}" and "{y_name}".

Can't find common titles at axis {axis}. {x_arg} has title "{x_title}" and {y_arg} has title "{y_title}".
```

An `NA` name is written without quotes, as `NA`.

Names are compared by `CHARSXP` pointer. The same text in two different
encodings compares as different, which is accepted.

## Examples

The outputs below are the intended behavior.

### 1. Identical names pass, different names error

```r
x <- array(1:2, 2, dimnames = list(c("r1", "r2")))
y <- array(1:2, 2, dimnames = list(c("a", "b")))

rray_add(x, x)
#> r1 r2
#>  2  4

rray_add(x, y)
#> Error in `rray_add()`:
#> ! Can't find common names at axis 1. `x` and `y` have different names at position 1: "r1" and "a".

rray_add(x, rray_set_names(y, NULL))
#> r1 r2
#>  2  4
```

### 2. An input without names has no say

```r
x <- array(1:4, c(2, 2), dimnames = list(c("r1", "r2"), NULL))
y <- array(5:8, c(2, 2), dimnames = list(NULL, c("c1", "c2")))

rray_add(x, y)
#>    c1 c2
#> r1  6 10
#> r2  8 12
```

Each input names a different axis, so nothing conflicts and both are kept.

### 3. A broadcast axis has no say on names

```r
x <- array(1:3, c(1, 3), dimnames = list("total", c("a", "b", "c")))
y <- array(1:6, c(2, 3), dimnames = list(c("r1", "r2"), c("a", "b", "c")))

rray_multiply(x, y)
#>    a b  c
#> r1 1 6 15
#> r2 2 8 18
```

`"total"` names a single row that gets repeated, so it is dropped rather than
compared. Axis 2 is compared, and agrees.

// Broadcasting of array names
//
// Assumes the inputs are validated arrays and are broadcastable to the
// `dimensions`. The caller typically checks all of this already.
static r_obj* rray_broadcast_names_fill(
  r_obj* out,
  r_obj* x,
  r_obj* dimensions,
  const bool* v_ignored
) {
  r_obj* x_names = rray_names(x, rray_args.x, r_lazy_null);
  if (x_names == r_null) {
    return out;
  }
  KEEP(x_names);

  r_obj* const* v_x_names = r_list_cbegin(x_names);

  r_obj* x_dimensions = KEEP(rray_dimensions(x, rray_args.x, r_lazy_null));
  const int* v_x_dimensions = r_int_cbegin(x_dimensions);
  const int x_dimensionality =
    rray_dimensionality_from_dimensions(x_dimensions);

  const int* v_dimensions = r_int_cbegin(dimensions);
  const int dimensionality = rray_dimensionality_from_dimensions(dimensions);

  r_keep_loc out_loc;
  KEEP_HERE(out, &out_loc);

  for (int i = 0; i < x_dimensionality; ++i) {
    if (v_ignored[i]) {
      continue;
    }
    if (v_x_names[i] == r_null) {
      // No names to contribute on this axis
      continue;
    }
    if (v_x_dimensions[i] != v_dimensions[i]) {
      // No names to contribute when axis is broadcast
      continue;
    }
    if (out != r_null && r_list_get(out, i) != r_null) {
      // Names already exist on this axis
      continue;
    }
    if (out == r_null) {
      out = r_alloc_list(dimensionality);
      KEEP_AT(out, out_loc);
    }
    r_list_poke(out, i, v_x_names[i]);
  }

  FREE(3);
  return out;
}

  struct rray_arg* arg,
  char* buf,
  r_ssize cur_size,
  r_ssize tot_size
) {
  if (arg->parent != NULL) {

    if (cur_size < 0) {

  const r_ssize written =
    arg->fill(arg->data, buf + cur_size, tot_size - cur_size);

struct rray_arg* new_subscript_arg(
  struct rray_arg* parent,
  r_obj* names,
  r_ssize n,
  r_ssize* p_i
) {
  r_obj* shelter = KEEP(r_alloc_list(2));

  r_list_poke(shelter, 1, names);

  p_data->self = (struct rray_arg){

    .parent = parent,
    .fill = &subscript_arg_fill,
    .data = p_data
  };
  p_data->names = names;
  p_data->n = n;
  p_data->p_i = p_i;

static r_ssize subscript_arg_fill(void* data, char* buf, r_ssize remaining) {
  struct subscript_arg_data* p_data = (struct subscript_arg_data*) data;

  const r_ssize i = *p_data->p_i;
  const r_ssize n = p_data->n;
  r_obj* names = p_data->names;

  if (i >= n) {
    r_stop_internal(
      "`i` of %" R_PRI_SSIZE " can't be past the end of %" R_PRI_SSIZE ".",
      i,
      n
    );
  }

  const size_t space = (size_t) remaining;
  const bool named = r_has_name_at(names, i);
  const bool child = !rray_arg_is_empty(p_data->self.parent);

  int len;

  if (child) {
    if (named) {
      len = snprintf(buf, space, "$%s", r_chr_get_c_string(names, i));
    } else {
      len = snprintf(buf, space, "[[%" R_PRI_SSIZE "]]", i + 1);
    }
  } else {
    if (named) {
      len = snprintf(buf, space, "%s", r_chr_get_c_string(names, i));
    } else {
      len = snprintf(buf, space, "..%" R_PRI_SSIZE, i + 1);
    }
  }

  if (len >= remaining) {
    return -1;
  }

  return len;
}

rray (said: "r-ray") is an array manipulation library for R. rray's goal is to
provide a consistent, powerful toolkit for array manipulation, usable on base R
arrays. It supports broadcasting throughout the entire package, which allows for
novel array operations popularized by [NumPy](https://numpy.org/) that have been
missing from the R ecosystem.

View [the website](https://rray.r-lib.org) to learn more about how to use rray.

```{r}
library(rray)
```

## Installation

[GitHub](https://github.com/) with:

```r
# install.packages("pak")

```

## What can it do?

rray reimagines array based operations on top of a concept called
*broadcasting*. If you are familiar with the [tidyverse recycling
rules](https://vctrs.r-lib.org/reference/theory-faq-recycling.html) that state
that a vector of size 1 can be *recycled* to any other size, then you're already
most of the way to understanding broadcasting. Broadcasting takes that principle
and applies it to each axis of an array. For example:

```{r}
#| error: true

x <- array(1:3, dim = c(1, 3))
x

y <- array(1:6, dim = c(2, 3))
y

# Error with base R, non-conformable arrays
x + y

# Broadcasts `x`'s first axis to match the 2x3 dimensions of `y`
rray_add(x, y)
```

Broadcasting is used throughout the entire package and allows you to elegantly
chain operations together. For example, you can sum down the rows and then
compute proportions by using a broadcasted divide.

```{r}
x <- array(1:6, dim = c(3, 2))
x

# Sum down the rows
sums <- rray_sum(x, axes = 1)
sums

# Compute proportions along the 1st dimension
rray_divide(x, sums)

# Equivalent base R syntax
sweep(x, 2, apply(x, 2, sum), "/")
```

When combining arrays with `rray_combine()`, broadcasting allows you to combine
in ways that base R cannot with the native `cbind()` and `rbind()` functions:

```{r}
#| error: true

a <- array(c(1, 2), dim = c(2, 1))
a

b <- array(c(3, 4), dim = c(1, 2))
b

# Error
cbind(a, b)

# `a` is first broadcast to have dimensions: (2, 2)
rray_combine(a, b, .axis = 1)

# Error
rbind(a, b)

# `b` is first broadcast to have dimensions: (2, 2)
rray_combine(a, b, .axis = 2)
```

## Acknowledgements

rray was originally written in 2018 and was backed by
[`xtensor`](https://github.com/QuantStack/xtensor). That original implementation
is archived as [DavisVaughan/rray1](https://github.com/DavisVaughan/rray1), but
its API served as the foundation for this rewrite.

rray uses a large amount of theory from
[`vctrs`](https://github.com/r-lib/vctrs) to be consistent and type stable. For
example, broadcasting is just an extension of the [tidyverse recycling
rules](https://vctrs.r-lib.org/reference/theory-faq-recycling.html), applied to
all axes of the array.

The original motivation for this package, and even for xtensor, is the excellent
Python library, NumPy. As far as I know, it has the original implementation of
broadcasting, and is a core library that a huge number of others are built on
top of.

In the past, the workhorse for flexibly binding arrays together has been the
abind package. This package has been a great source of inspiration and has
served as a nice benchmark for rray.
