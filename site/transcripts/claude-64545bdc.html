  switch (r_typeof(x)) {
  case R_TYPE_logical: {
    const int* v_x = r_lgl_cbegin(x);

    r_obj* out = KEEP(r_alloc_logical(size));

    FREE(1);
    return out;
  }

I left thread 5 (line 125) open and unchanged because you asked to talk it over locally. Here is my take.

Do we need to worry about attributes? No. R calls our Duplicate method from altrep_DuplicateEX_default() (src/main/altrep.c:740). That function then replaces the result's attributes with the wrapper's own: a shallow copy of them, or none if the wrapper has none. Whatever attributes our method returns get overwritten.

Should we use Rf_shallow_duplicate() on the data? Either would be correct, for the reason above. Two differences:

  • Wasted work: wrapper_data(x) is often the user's original object, which can carry dims and names. Rf_shallow_duplicate() would copy those attributes only for R to throw them away. r_clone_data() copies only the data.

  • ALTREP data: now that ALTREP inputs are wrapped as is, the data can be something like a compact sequence. Rf_shallow_duplicate() would ask that object to duplicate itself, which may keep it compact. r_clone_data() reads through r_int_cbegin(), which forces the sequence to expand. That leans toward Rf_shallow_duplicate(), but only matters if keeping the copy compact is worth something to us.

My recommendation is to keep r_clone_data() unless you care about the ALTREP point.
