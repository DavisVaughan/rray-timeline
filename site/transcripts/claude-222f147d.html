Yes, you can. vctrs doesn't do it, though. Its codecov.yml is identical to rray's, and it has no .covrignore file. So vctrs's coverage numbers include its vendored src/rlang/ too.

There are two ways to exclude it.

  1. In Codecov. Add an ignore block to codecov.yml:

    ignore:
  - "src/rlang"

    Codecov drops those files from the report when it processes the upload. The project and patch numbers then cover only rray's own code. This is a one-file change.

  2. In covr. Add a .covrignore file at the package root that contains src/rlang/*, and list it in .Rbuildignore. covr reads this file and leaves those files out of the results. That keeps them out of cobertura.xml itself, and also out of local covr::report() runs.

I'd go with option 1. It's the smallest change and it does what you want on Codecov. Option 2 is only worth it if you also want local covr reports to skip the vendored code.

I haven't confirmed the exact path that covr writes into cobertura.xml (src/rlang/... vs. something else). It's worth checking that on the first run after the change. Should I add the ignore block?
