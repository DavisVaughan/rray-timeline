## Subscripts and locations

A subscript describes a set of positions on an axis. It can be negative,
logical, character, missing, or `NULL`. Subscript normalization produces a
one-dimensional sequence of positive or missing locations. Subscripts on
different axes form a Cartesian product.

A location array has a narrower meaning. Each non-missing element is one
positive, one-based position on one source axis. Its dimensions connect that
position to a point in the result. Zero and negative locations cannot mean
complement because every element must identify one source position.

This gives the public functions stable contracts:

- `D` be the source dimensions.
- `n` be the dimensionality of `x`.

- `L[j]` be the location array for `S[j]`.

Every supplied array gives one source coordinate at each point in `G`:

```text
source[S[j]] = broadcast(L[j])[g]
```

The selected coordinates are always paired at the same point `g`. Singleton
dimensions and missing trailing dimensions follow rray's left-aligned
broadcasting rules.

Each element of `locations` must be a bare integer vector or array. Bare
vectors normalize to one-dimensional arrays. Factors and other classed integer
objects are errors.

Every non-missing location must be positive, one based, and no greater than the
dimension of its source axis.

- Positive integers identify one position.
- Zero and negative integers are errors.
- Missing locations produce missing output when reading.
- Missing locations are errors when assigning.
- Out-of-bounds locations are errors.

Validation happens before allocating or copying the result. Every supplied
location is validated even when another result axis has dimension zero.

The first version should accept only integer locations. Logical values are
masks, character values require name matching, and doubles weaken the contract
without adding addressing power. Those inputs already belong to slicing or
extraction.

- Explicit axes must be valid, unique, and strictly increasing.

- With `locations = list()` and `axes = NULL`, no source axes are selected.

- Selecting only some source axes requires explicit `axes`.

Yes, but only after lowering it to ordinary array coordinates.

Base R supports a coordinate matrix:

x[coordinates]

Each row of coordinates identifies one element of x. This directly represents the fully pointwise case of rray_index():

rows <- c(1L, 3L, 2L)
cols <- c(4L, 1L, 3L)

coordinates <- cbind(rows, cols)
x[coordinates]

For partial indexing, identity indexing, or cross = TRUE, base R has no compact equivalent. You must expand the indexing operation into either:

  • A coordinate matrix with one row for every output element, or
  • An array of flat linear positions, then reshape the result.

Conceptually:

positions <- array(<linear positions in x>, output_dimensions)
out <- array(x[positions], dim = dim(positions))

That flat-position array is probably the best base R representation of a fully resolved rray_index() plan. It can express broadcasting, identity axes, crossed axes, missing locations, and repeated locations. However, base R does not retain the intended relationship between source axes and location arrays. That structure has already been compiled away into linear positions.

So the short answer is:

  • Coordinate matrices represent full pointwise indexing directly.
  • Arrays of linear positions can represent any resolved rray_index() operation.
  • Base R has no native high-level representation equivalent to locations + axes + cross.

Yes. Every rray_index() example can be lowered to base R’s matrix indexing system. Each row of an integer matrix supplies one complete source coordinate:

x[coordinate_matrix]

Because matrix indexing returns a vector, array() restores the intended output dimensions.

A small setup helper keeps the examples readable while leaving the actual indexing to base R:

point_subset <- function(x, coordinates, dimensions) {
  array(x[coordinates], dim = dimensions)
}

1. Full pointwise indexing

x <- matrix(1:12, nrow = 3)

rows <- c(1L, 3L, 2L)
columns <- c(4L, 1L, 3L)

coordinates <- cbind(rows, columns)

out <- point_subset(
  x,
  coordinates,
  dimensions = 3L
)

out
# [1] 10  3  8

The direct base R expression is:

array(x[cbind(rows, columns)], dim = 3L)

This is the case that base R represents directly and compactly.

2. Cartesian indexing through shaped locations

rows <- array(c(3L, 1L), c(2L, 1L))
columns <- array(c(4L, 2L, 1L), c(1L, 3L))

First perform the broadcasts explicitly:

rows_broadcast <- rows[, rep(1L, 3L), drop = FALSE]
columns_broadcast <- columns[rep(1L, 2L), , drop = FALSE]

rows_broadcast
#      [,1] [,2] [,3]
# [1,]    3    3    3
# [2,]    1    1    1

columns_broadcast
#      [,1] [,2] [,3]
# [1,]    4    2    1
# [2,]    4    2    1

Flattening both arrays in R’s column-major order forms the coordinate rows:

coordinates <- cbind(
  row = c(rows_broadcast),
  column = c(columns_broadcast)
)

out <- point_subset(
  x,
  coordinates,
  dimensions = c(2L, 3L)
)

out
#      [,1] [,2] [,3]
# [1,]   12    6    3
# [2,]   10    4    1

Base R does not broadcast these arrays automatically. The broadcast must be performed before creating the matrix subscript.

3. Identity-paired single-axis indexing

x <- matrix(
  c(
    10, 20, 30, 40,
    50, 60, 70, 80
  ),
  nrow = 2,
  byrow = TRUE
)

locations <- rbind(
  c(4L, 1L),
  c(2L, 3L)
)

The source row is the identity coordinate. The source column comes from locations:

identity_rows <- row(locations)

coordinates <- cbind(
  row = c(identity_rows),
  column = c(locations)
)

out <- point_subset(
  x,
  coordinates,
  dimensions = dim(locations)
)

out
#      [,1] [,2]
# [1,]   40   10
# [2,]   60   70

This represents:

out[row, column] = x[row, locations[row, column]]

4. Crossed single-axis indexing

Here the source rows are independent of the two location dimensions.

out_dimensions <- c(
  nrow(x),
  dim(locations)

# c(2, 2, 2)

out_points <- arrayInd(
  seq_len(prod(out_dimensions)),
  out_dimensions

head(out_points)
# Columns represent:
# source row, location row, location column

Look up the column location for each output point:

selected_columns <- locations[
  cbind(out_points[, 2L], out_points[, 3L])

coordinates <- cbind(
  row = out_points[, 1L],

# [2,]   80   60

out[, , 2L]
#      [,1] [,2]
# [1,]   10   30
# [2,]   50   70

The expanded matrix index encodes:

out[a, j, k] = x[a, locations[j, k]]

coordinates <- cbind(

Base R allows us to express the resulting coordinates, but it does not enforce rray’s broadcasting rule. For example, code outside the subset operation must reject a location dimension of four when the source row dimension is three.

6. Multiple selected axes with identities

Here is a concrete version of the abstract (A, B, C) example:

x <- array(seq_len(3L * 2L * 4L), c(3L, 2L, 4L))

row_locations <- array(
  c(1L, 3L, 2L, 1L),
  c(2L, 1L, 2L)
)

depth_locations <- array(
  c(
    4L, 1L,
    3L, 2L,
    2L, 4L,
    1L, 3L
  ),
  c(2L, 2L, 2L)
)

row_locations broadcasts along the second axis:

row_locations_broadcast <- row_locations[
  ,
  rep(1L, dim(x)[2L]),
  ,
  drop = FALSE
]

out_dimensions <- c(2L, 2L, 2L)

out_points <- arrayInd(
  seq_len(prod(out_dimensions)),
  out_dimensions
)

selected_rows <- row_locations_broadcast[out_points]
selected_depths <- depth_locations[out_points]

coordinates <- cbind(
  row = selected_rows,
  column = out_points[, 2L],
  depth = selected_depths
)

out <- point_subset(
  x,
  coordinates,
  dimensions = out_dimensions
)

The coordinate matrix represents:

out[j, b, k] =
  x[row_locations[j, b, k], b, depth_locations[j, b, k]]

The identity coordinate for source axis 2 is out_points[, 2L].

This represents:

out[j, k, b] =
  x[row_locations[j, k], b, depth_locations[j, k]]

There are no unselected source axes, so crossed and identity-paired indexing are identical.

8. Empty location list

With no selected axes, the result is simply a full subset:

out <- x[]

For an array, x[] retains its dimensions and dimension names.

A normalized copy of a bare vector can be obtained with:

x <- 1:4
out <- array(x[], dim = length(x))

Assignment with repeated points

Base R also supports coordinate-matrix assignment:

x <- matrix(
  c(
    10, 20, 30, 40,
    50, 60, 70, 80
  ),
  nrow = 2,
  byrow = TRUE
)

rows <- c(1L, 1L, 2L)
columns <- c(2L, 2L, 4L)
value <- c(100, 200, 300)

coordinates <- cbind(rows, columns)

x[coordinates] <- value

x
#      [,1] [,2] [,3] [,4]
# [1,]   10  200   30   40
# [2,]   50   60   70  300

The coordinate (1, 2) occurs twice. Base R processes the replacements in order, so the final value, 200, wins.

Missing locations

A row containing NA in a matrix subscript produces a missing result:

x <- matrix(1:6, nrow = 2)

coordinates <- rbind(
  c(1L, 1L),
  c(NA_integer_, 2L),
  c(2L, 3L)
)

x[coordinates]
# [1]  1 NA  6

Reshaping gives rray’s array result:

array(x[coordinates], dim = 3L)

Base R also supplies the desired type-specific missing values for logical, integer, double, complex, character, raw, and list arrays.

For assignment, base R rejects missing matrix-subscript coordinates:

x[coordinates] <- 1:3
# Error

Orthogonal slicing lowered to matrix indexing

For three ordinary positive subscripts:

i <- c(2L, 1L)
j <- c(3L, 1L)
k <- c(2L, 4L)

Construct the Cartesian output grid:

grid <- expand.grid(
  i = i,
  j = j,
  k = k

coordinates <- as.matrix(grid)

out <- point_subset(
  x,
  coordinates,
  dimensions = c(length(i), length(j), length(k))

This is the fully expanded base R representation of the proposed lowering from rray_slice() to rray_index().

For ordinary base R slicing, the simpler expression remains:

x[i, j, k, drop = FALSE]

This is why ordinary slicing should remain a separate operation.

You are also right about names. I omitted them, and that omission made the base R translation look more complete than it really is.

Consider identity-paired indexing:

x <- matrix(
  c(
    10, 20, 30, 40,
    50, 60, 70, 80
  ),
  nrow = 2,
  byrow = TRUE,
  dimnames = list(
    row = c("r1", "r2"),
    column = c("c1", "c2", "c3", "c4")
  )
)

locations <- matrix(
  c(4L, 2L, 1L, 3L),
  nrow = 2,
  dimnames = list(
    row = c("ignored-1", "ignored-2"),
    selection = c("first", "second")
  )
)

The base R coordinate calculation is:

coordinates <- cbind(
  row = c(row(locations)),
  column = c(locations)
)

values <- x[coordinates]

But values no longer contains enough information to reconstruct the desired names. We must supply them manually:

out <- array(
  values,
  dim = dim(locations),
  dimnames = list(
    row = dimnames(x)[[1L]],
    selection = dimnames(locations)[[2L]]
  )
)

out
#     selection
# row  first second
#   r1    40     10
#   r2    60     70

That manual name calculation encodes several semantic decisions:

  • The unselected row axis is an identity axis, so it keeps the row names from x.
  • The selected column axis drops the column names from x.
  • The corresponding output dimension gets names from locations.
  • The first dimension names on locations do not replace the source row names.

For cross = TRUE, the name arrangement changes:

out_dimensions <- c(nrow(x), dim(locations))

out_points <- arrayInd(
  seq_len(prod(out_dimensions)),
  out_dimensions
)

coordinates <- cbind(
  row = out_points[, 1L],
  column = locations[
    cbind(out_points[, 2L], out_points[, 3L])
  ]
)

out <- array(
  x[coordinates],
  dim = out_dimensions,
  dimnames = list(
    row = dimnames(x)[[1L]],
    location_row = dimnames(locations)[[1L]],
    selection = dimnames(locations)[[2L]]
  )
)

Here the source row axis remains independent, so it keeps the source row names. Both inserted location dimensions get their names from locations.

This is where rray_index() starts providing substantial value. A base R coordinate matrix represents only the final element addresses. It loses:

  • Which axes were selected.
  • Which axes were identities.
  • Which axes were crossed.
  • Which dimensions came from broadcasting.
  • Where output dimensions should be inserted.
  • Which source names remain meaningful.
  • Which location names should populate the result.

You can encode all of that in a linear-position array carrying dim and dimnames:

index <- array(
  linear_positions,
  dim = output_dimensions,
  dimnames = output_names
)

out <- array(
  x[c(index)],
  dim = dim(index),
  dimnames = dimnames(index)
)

That is a complete base R representation of a resolved indexing plan. The hard part is producing index, especially its dimensions and names. That production step is essentially the work rray_index() performs.

My judgment would be:

  • rray_index_axis(cross = FALSE) has strong public value. It is the natural consumer of rray_locate_min() and similar functions.
  • rray_index_axis(cross = TRUE) also has clear value for multidimensional location arrays. Base R’s ordinary axis subsetting only covers the simple vector case.
  • General rray_index() is valuable as a common engine and an advanced escape hatch.
  • General multi-axis partial indexing is probably too specialized to be a common user operation.
  • Name propagation materially strengthens the case for the API because base R’s matrix indexing discards the structure needed to determine names.

If keeping the public API small is important, I would seriously consider exposing rray_index_axis() first and initially keeping the general multi-axis operation internal. The single-axis operation supplies the clearest functionality that base R is missing.
