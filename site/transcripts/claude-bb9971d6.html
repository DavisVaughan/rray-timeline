+# Titles plan
+
+## Goal
+
+Every function that takes one array and returns one array should keep the
+titles of `x` wherever its axes keep their meaning. Titles are the names on
+the dimnames list:
+
+```r
+x <- array(1:24, c(2, 3, 4), dimnames = list(A = c("a", "b"), B = NULL, C = NULL))
+
+rray_titles(x)
+# [1] "A" "B" "C"
+```
+
+Binary and n-ary functions are out of scope until we settle how names combine
+across inputs. See [Out of scope](#out-of-scope).
+
+## Rules
+
+These were decided up front and apply to every step.
+
+- A title labels an axis, not its positions. An axis that keeps its identity
+  keeps its title, even when it loses its names. `rray_sum(x, axes = 2)` keeps
+  title `"B"` on axis 2.
+
+- The result has a titles vector exactly when `x` has one. A new axis gets
+  the title `""`. An all `""` titles vector is never turned into `NULL`. This
+  matches `rray_set_axis_title(x, axis, NULL)`, which already leaves `""` in
+  place.
+
+- Titles can exist with no axis names at all. The dimnames list is then all
+  `NULL` elements, like `list(A = NULL, B = NULL)`. Every helper must handle
+  this case, which is the main trap: most names helpers only allocate their
+  output list when some axis has names.
+
+- A function that drops all names drops all titles. Today that is
+  `rray_extract()`, `rray_index()`, and `rray_set_dimensions()`.
+
+- `rray_set_names(x, names)` replaces the whole dimnames list. The names of
+  `names` become the titles of `x`, so an unnamed list drops them and `NULL`
+  clears everything.
+
+- `rray_broadcast()` is left alone for now, see [Out of scope](#out-of-scope).
+

+
+## Implementation pattern
+
+Each step adds titles to an existing names helper rather than adding a new
+code path. The pattern is the same everywhere:
+
+1. Read `x_titles = r_names(x_names)` next to the existing `x_names`. It is
+   protected through `x`.
+
+2. If `x_titles != r_null`, allocate the output names list up front instead of
+   lazily, so a titles-only input still gets a list.
+
+3. Either reuse `x_titles` unchanged (when the result has the same axes as
+   `x`) or build an `out_titles` character vector in the same loop that builds
+   the output names (when axes move, appear, or disappear).
+
+4. Poke the titles onto the output list with `r_attrib_poke_names()`.
+
+`r_alloc_character()` fills with `""`, so new axes need no explicit poke.

# Integer coordinate indexing plan

## Recommendation

Add one fully specified coordinate function and one directional one-axis
specialization:

```r
rray_index(x, ...)
rray_index_assign(x, ..., value)

rray_index_axis(x, i, ..., axis)
rray_index_assign_axis(x, i, ..., axis, value)
```

`rray_index()` requires exactly one integer coordinate array for every source
axis. The arrays broadcast to common dimensions and are read pointwise. The
common dimensions are the result dimensions.

`rray_index_axis()` accepts one integer array for the selected source axis and
supplies identity coordinates for every other axis. `i` must broadcast to the
dimensions of `x` outside `axis`. The result has the same dimensionality as
`x`, every unselected axis keeps its source dimension, and only the selected
axis can change.

Every source coordinate is explicit. Different partial indexing behaviors are
represented by shaping full coordinate arrays in different ways.

The complete family is:

| Operation | Read | Assign |
|---|---|---|
| Orthogonal subscripts | `rray_slice()` | `rray_slice_assign()` |
| One-axis subscript | `rray_slice_axis()` | `rray_slice_assign_axis()` |
| First axis subscript | `rray_slice_rows()` | `rray_slice_assign_rows()` |
| Second axis subscript | `rray_slice_columns()` | `rray_slice_assign_columns()` |
| One-axis coordinate array | `rray_index_axis()` | `rray_index_assign_axis()` |
| Full coordinate arrays | `rray_index()` | `rray_index_assign()` |
| Flat subscript or point matrix | `rray_extract()` | `rray_extract_assign()` |

Do not add replacement functions. Every `_assign()` function returns a
modified copy of `x`.

## Subscripts and coordinates

A subscript describes a set of positions. It can be negative, logical,
character, missing, or `NULL`. Subscript normalization produces a
one-dimensional sequence of positive or missing locations. Subscripts on
different axes form a Cartesian product.

A coordinate array has a narrower meaning. Each non-missing element is one
positive, one-based position on one source axis. Its dimensions connect that
coordinate to an output point. Coordinates on different source axes broadcast
and pair pointwise.

```r
rray_slice_axis(x, -1L, axis = 2L)
# Complement selection

rray_index_axis(x, array(-1L, rray_dimensions(x)), axis = 2L)
# Error: coordinates must be positive
```

The function name determines the input rules. The shape or class of `i` never
changes a slice into coordinate indexing.

## Subscripts and coordinates

A subscript describes a set of positions. It can be negative, logical,
character, missing, or `NULL`. Subscript normalization produces a
one-dimensional sequence of positive or missing locations. Subscripts on
different axes form a Cartesian product.

A coordinate array has a narrower meaning. Each non-missing element is one
positive, one-based position on one source axis. Its dimensions connect that
coordinate to an output point. Coordinates on different source axes broadcast
and pair pointwise.

```r
rray_slice_axis(x, -1L, axis = 2L)
# Complement selection

rray_index_axis(x, array(-1L, rray_dimensions(x)), axis = 2L)
# Error: coordinates must be positive
```

The function name determines the input rules. The shape or class of `i` never
changes a slice into coordinate indexing.

## Full coordinate model

Let:

- `D` be the source dimensions.
- `n` be the dimensionality of `x`.
- `L[a]` be the coordinate array supplied for source axis `a`.
- `G` be the common dimensions of all `L[a]`.

`rray_index()` requires exactly `n` coordinate arrays. At every output point
`g` in `G`, each broadcast coordinate array supplies one component of the
source coordinate:

```text
source[a] = broadcast(L[a])[g]
out[g] = x[source[1], source[2], ..., source[n]]
```

The result dimensions are exactly `G`:

```text
out_dimensions = common_dimensions(L[1], ..., L[n])
```

The output can have lower, equal, or greater dimensionality than `x`. There is
no source-axis placement rule because every output axis belongs to the common
coordinate space.

Singleton dimensions and missing trailing dimensions follow rray's
left-aligned broadcasting rules.

## Coordinate validation

Each argument in `...` and `i` in `rray_index_axis()` must be a bare integer
vector or array. Bare vectors are one-dimensional arrays. Factors and other
classed integer objects are errors.

Every non-missing coordinate must be positive, one based, and no greater than
the dimension of its source axis:

- Positive integers identify one source position.
- Zero and negative integers are errors.
- Missing coordinates produce missing output when reading.
- Missing coordinates are errors when assigning.
- Out-of-bounds coordinates are errors.

Logical, character, and double inputs are errors. Logical values are masks,
character values require name matching, and doubles weaken the strict
coordinate contract. Those inputs belong to slicing or extraction.

Validation happens before allocating or copying the result. Every coordinate
array is validated even when the common result has size zero.

# Names and titles across several inputs

## Status

Draft. Decisions so far are marked as decided, everything else is in
[Open questions](#open-questions).

## Goal

Every function that builds one result from several inputs should:

- Keep titles, by the same rules the single-array functions already follow.

- Let the caller choose what happens when inputs disagree about names, through
  a `names` argument.

The functions in scope are the ones listed in `plans/titles.md`. Once this plan
is done, that file is deleted.

## Where the work lives

Almost everything goes through `src/broadcast-names.c`:

| Caller | Helper |
|---|---|
| `rray_broadcast()` | `rray_broadcast_names()` |
| Arithmetic, comparison, `rray_equal()`, logical, `rray_pmax()`, `rray_pmin()` | `rray_broadcast_names2()` |
| `rray_combine()`, and `rray_stack()` through it | `rray_broadcast_names_common_opts()` |

`rray_broadcast_common()` calls `rray_broadcast()` once per input, so it never
combines names across inputs. It only needs the title rule for broadcast axes.

`rray_stack()` also goes through `rray_expand_dimensionality()`, which drops
titles today.

## Today's names rules

For each axis, independently:

- An input contributes names only if it has names on that axis and its
  dimension there is not broadcast.

- The first input that contributes wins. Later inputs are ignored, even when
  they disagree.

```r
x <- array(1:2, 2, dimnames = list(c("r1", "r2")))
y <- array(1:2, 2, dimnames = list(c("a", "b")))

rray_names(rray_add(x, y))
# [[1]]
# [1] "r1" "r2"
```

This is per axis, unlike base R, which takes the whole dimnames of the first
input that has any.

## Title rules

- A broadcast axis keeps its title (decided). A title labels the axis, not its
  positions, the same reasoning that keeps the title on a reduced axis.

  ```r
  m <- array(1:12, c(1, 3, 4), dimnames = list(A = NULL, B = NULL, C = NULL))

  rray_titles(rray_broadcast(m, c(2, 3, 4)))
  # [1] "A" "B" "C"
  ```

  This also removes today's irregularity where `rray_broadcast()` keeps titles
  only on a no-op.

- The input that supplies an axis's names also supplies its title (decided).

- When two inputs disagree on a title, the first wins silently (decided, but
  see the `"error"` question below).

- The result has a titles vector exactly when some input has one. Axes nobody
  titled get `""`.

- What happens on an axis that ends up with no names is open, see
  [Open questions](#open-questions).

For `rray_combine()`, the combine axis follows the same rules: its title comes
from the first input that has names on that axis. Its names are still pasted
together from every input, as today.

For `rray_stack()`, the new axis gets the title `""`.

## The `names` argument

A string that picks how names on one axis are merged when several inputs
contribute to it. It never affects broadcast axes, which contribute nothing,
or the combine axis of `rray_combine()`, which pastes names together.

### `"first"`

Today's behavior. The first contributing input wins.

```r
x <- array(1:2, 2, dimnames = list(c("r1", "r2")))
y <- array(1:2, 2, dimnames = list(c("a", "b")))

rray_names(rray_add(x, y, names = "first"))[[1]]
# [1] "r1" "r2"
```

### `"error"`

Every contributing input must agree, otherwise error.

```r
rray_add(x, y, names = "error")
# Error in `rray_add()`:
# ! Can't combine names on axis 1.
# ✖ `x` has names "r1" and "r2".
# ✖ `y` has names "a" and "b".

rray_names(rray_add(x, x, names = "error"))[[1]]
# [1] "r1" "r2"
```

### `"coalesce"`

Per position, the first non-empty name wins. Useful after `rray_combine()`,
which fills unnamed inputs with `""`.

```r
x <- array(1:2, 2, dimnames = list(c("r1", "")))
y <- array(1:2, 2, dimnames = list(c("a", "b")))

rray_names(rray_add(x, y, names = "coalesce"))[[1]]
# [1] "r1" "b"
```

With fully named inputs this is the same as `"first"`.

### Considered and left out

- `"drop"`: never keep names. The same as calling `rray_set_names(out, NULL)`
  afterwards, so it adds an option without adding a capability.

- `"consensus"`: keep names only when every contributor agrees, otherwise drop
  them on that axis. Silent data loss is the worst outcome of the three, it
  hides the same mistake `"error"` catches.

- A global option like `options(rray.names = "error")`. Global state that
  changes results makes code behave differently depending on who runs it.

### Which functions get it

- Arithmetic, comparison, `rray_equal()`, `rray_not_equal()`, logical,
  `rray_pmax()`, `rray_pmin()`: `names`, after `...`, like `na_rm` on
  `rray_pmax()`.

- `rray_combine()`, `rray_stack()`: `.names`, matching `.axis`, since their
  `...` takes the data.

- Not `rray_broadcast()` or `rray_broadcast_common()`, which never merge names
  across inputs.

- Not `rray_if_else()`, which drops all names on purpose.

## C design

One core helper replaces `rray_broadcast_names()`, `rray_broadcast_names2()`,
and `rray_broadcast_names_common_opts()`:

```c
enum rray_names_mode {
  RRAY_NAMES_FIRST,
  RRAY_NAMES_ERROR,
  RRAY_NAMES_COALESCE
};

r_obj* rray_broadcast_names_common(
  r_obj* xs,
  r_obj* dimensions,
  enum rray_names_mode mode,
  const bool* v_ignored,
  struct rray_arg* arg,
  struct r_lazy error_call
);
```

It builds the full dimnames list, names and titles together, in one pass over
the inputs. `arg` and `error_call` exist for the `"error"` message.
`rray_broadcast_names()` and `rray_broadcast_names2()` stay as thin wrappers
so call sites don't change shape, but `rray_broadcast_names2()` must not
allocate a list just to call the core.

Titles force the output list to be allocated up front, the same trap as in the
single-array work: a titles-only input has no names to trigger the lazy
allocation.

`"first"` can stop early once every axis has names and a title.

The `names` string is converted to the enum once, in the FFI wrapper, with an
`arg_as_names_mode()` helper in `src/arg.c`.

1. Identical names pass, different names error

x <- array(1:2, 2, dimnames = list(c("r1", "r2")))
y <- array(1:2, 2, dimnames = list(c("a", "b")))

rray_add(x, x)
#> r1 r2
#>  2  4

rray_add(x, y)
#> Error in `rray_add()`:
#> ! Can't find common names at axis 1. `x` and `y` have different names at position 1: "r1" and "a".

#> r1 r2
#>  2  4

The wording mirrors today's Can't find common dimensions at axis 1. The message reports the first position that differs, which stays readable when there are many names.

2. An input without names has no say

x <- array(1:4, c(2, 2), dimnames = list(c("r1", "r2"), NULL))
y <- array(5:8, c(2, 2), dimnames = list(NULL, c("c1", "c2")))

rray_add(x, y)
#>    c1 c2
#> r1  6 10
#> r2  8 12

Each input names a different axis, so nothing conflicts and both sets of names are kept.

3. A broadcast axis has no say on names

x <- array(1:3, c(1, 3), dimnames = list("total", c("a", "b", "c")))
y <- array(1:6, c(2, 3), dimnames = list(c("r1", "r2"), c("a", "b", "c")))

rray_multiply(x, y)
#>    a b  c
#> r1 1 6 15
#> r2 2 8 18

"total" labels a single row that gets repeated, so it's dropped rather than compared with r1 and r2. Axis 2 is compared, and the names agree.

x <- array(1:2, 2, dimnames = list(c("r1", "")))

rray_add(x, y)
#> Error in `rray_add()`:
#> ! Can't find common names at axis 1. `x` and `y` have different names at position 2: "" and "r2".

x <- array(1:4, c(2, 2), dimnames = list(c("r1", "r2"), c("c1", "c2")))

#> r2 40 80

# Names and titles across several inputs

## Goal

When a function builds one result from several inputs, the inputs must agree
on names and titles. If they don't, the function errors instead of silently
picking one input's names.

```r
jan <- array(1:2, 2, dimnames = list(c("north", "south")))
feb <- array(3:4, 2, dimnames = list(c("south", "north")))

rray_stack(jan = jan, feb = feb, .axis = 2)
#> Error in `rray_stack()`:
#> ! Can't find common names at axis 1. `jan` and `feb` have different names at position 1: "north" and "south".
```

Today this succeeds, labels every row with the order of `jan`, and the `feb`
column is silently wrong.

There is no argument to choose another behavior. To resolve a conflict, remove
the names from one input with `rray_set_names()`, which returns a view and
does not copy the data.

At the same time, titles stop being dropped by these functions.

## Functions in scope

| Function | Names | Titles |
|---|---|---|
| `rray_add()`, `rray_subtract()`, `rray_multiply()`, `rray_divide()`, `rray_exponentiate()` | Must agree | Must agree, kept |
| `rray_pmax()`, `rray_pmin()` | Must agree | Must agree, kept |
| `rray_combine()` | Must agree, except on `.axis` | Must agree, kept |
| `rray_stack()` | Must agree, new axis from the names of `...` | Must agree, kept, `""` on the new axis |
| `rray_broadcast()`, `rray_broadcast_common()` | One input at a time, never errors | Kept, including on broadcast axes |
| `rray_equal()`, `rray_not_equal()`, `rray_greater_than()`, `rray_greater_than_or_equal()`, `rray_less_than()`, `rray_less_than_or_equal()` | Dropped | Dropped |
| `rray_and()`, `rray_or()`, `rray_xor()` | Dropped | Dropped |
| `rray_if_else()` | Already dropped, unchanged | Already dropped, unchanged |

## Names rules

For each axis of the result:

- An input has a say only if it has names on that axis and its dimension
  there is not broadcast. An axis of dimension 1 that stays 1 is not
  broadcast.

- An input that is missing the axis, because it has a lower dimensionality,
  has no say.

- Every input with a say must have exactly the same names. There are no
  holes: `c("r1", "")` and `c("r1", "r2")` disagree. `NA` agrees only with
  `NA`.

- If they agree, the result has those names. If no input has a say, the axis
  has no names.

- The combine axis of `rray_combine()` is not checked. Its names are pasted
  together from every input, with `""` for unnamed inputs, as today.

- The new axis of `rray_stack()` is not checked. Its names come from the names
  of `...`, as today.

## Titles rules

Titles are the names on the dimnames list.

- An empty title, or no titles at all, has no say.

- Every other title on an axis must agree, including titles from inputs that
  broadcast on that axis or have no names there. A title labels the axis, not
  its positions, so it survives broadcasting.

- Because all non-empty titles must agree, the title of an axis is that one
  agreed title, or `""` when nobody has one.

- The result has a titles vector exactly when some input has one.

- The combine axis of `rray_combine()` is checked like any other axis.

- The new axis of `rray_stack()` gets the title `""`.

- `rray_broadcast()` keeps every title of `x`, so it no longer depends on
  whether any broadcasting happened.

## Errors

Inputs are visited left to right, and the axes of each input left to right.
Names are checked before titles on each axis. The first disagreement errors.

The error names the first input that had a say on the axis and the first input
that disagrees with it. For names, it reports the first position that differs.
The wording mirrors the existing `Can't find common dimensions` error in
`src/dimensions.c`.

```text
Can't find common names at axis {axis}. {x_arg} and {y_arg} have different names at position {position}: "{x_name}" and "{y_name}".

Can't find common titles at axis {axis}. {x_arg} has title "{x_title}" and {y_arg} has title "{y_title}".
```

An `NA` name is written without quotes, as `NA`.

Names are compared by `CHARSXP` pointer. The same text in two different
encodings compares as different, which is accepted.

```r

#> r1 r2
#>  2  4

rray_add(x, y)
#> Error in `rray_add()`:
#> ! Can't find common names at axis 1. `x` and `y` have different names at position 1: "r1" and "a".

rray_add(x, rray_set_names(y, NULL))
#> r1 r2
#>  2  4
```

```r
x <- array(1:4, c(2, 2), dimnames = list(c("r1", "r2"), NULL))

#> r1  6 10
#> r2  8 12
```
