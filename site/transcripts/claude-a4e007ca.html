Things to decide

  • Group 1 is the clear win. It also matches what group 3 already does (rray_rep(), rray_roll(), rray_move_axes(), rray_split()). Today the package is split between the two styles, so making this change gives you one style.

  • Group 2 needs a decision about i. rray_slice_axis() keeps i positional, as in (x, i, ..., axis). If rray_slice_rows() and rray_extract() move i behind the dots, the package would treat i two different ways. I would keep i positional everywhere.

  • The setters in group 2 are a judgment call. rray_set_names(x, names) reads clearly without a name, and it pipes well with |>. rray_broadcast(x, dimensions) and rray_set_dimensions() lean the other way, because rray_if_else() and rray_split() already require dimensions by name.

Davis

How do you feel about this change from a user perspective ?

Claude

I like it for anything that takes an axis, and I would not apply it to every function.

Why it helps users

  • A bare number is ambiguous in rray. Compare these two calls:

    rray_add(x, 2)
rray_sum(x, 2)

    They look the same, but the first adds the number 2 and the second sums along axis 2. In a package where most functions broadcast against a second input, a bare 2 naturally reads as data. rray_sum(x, axes = 2) removes the doubt.

  • It matches what people already know. NumPy users write np.sum(x, axis=1) out of habit, and code from data analysts almost always names the axis anyway. So most users would not even notice the requirement.

  • The package becomes consistent. rray_rep(), rray_roll(), rray_split() and rray_move_axes() already require names. Right now a user has to remember which functions do and which do not. After the change, the rule is simply "axes are always named".

  • It leaves room to grow. You can add new arguments later without breaking positional calls.

What it costs

  • A little more typing, mostly at the console. rray_sum(x, axes = 1) versus rray_sum(x, 1). That is a small price.

  • A clear error matters. rray_sum(x, 1) must fail with a helpful message, not a confusing "argument axes is missing". rlang's check_dots_empty() already gives a hint along the lines of "Did you forget to name an argument?". Make sure every function gets that hint.

Where I would stop

I would not extend the rule to group 2 from my last reply:

  • rray_set_names(x, names) and rray_set_titles(x, titles) are already clear. Forcing names = there is noise, especially in a |> chain.

  • i in rray_extract() and rray_slice_rows() should stay positional to match rray_slice_axis(x, i, ..., axis). Indexing is the main point of those functions.

  • rray_broadcast(x, dimensions) is the only borderline case. rray_if_else() and rray_split() already name dimensions, so requiring it would be consistent. But rray_broadcast(x, c(2, 3)) is not ambiguous, so I would leave it alone.

So my suggested rule: anything that names an axis must be passed by name, and everything else stays as it is. That rule is easy to explain in one line, and it targets exactly the calls that confuse people.

A rule that covers it

Require a name when a bare value could be mistaken for something else. That gives the same answer as everything we discussed so far:

  • rray_sum(x, 2): the 2 could be data, so name it.

  • rray_axis_names(x, 2): the function name says "axis", so no name is needed.

  • rray_rep(x, 2, 1), rray_roll(), rray_split(), rray_move_axes(): two numbers side by side, and you cannot tell which is which. Name them. These functions already do this.

  • rray_slice_axis(x, 1:2, ..., axis): "axis" is in the name, but i and axis are both numbers, so axis still has to be named. This one already does that too.

  • rray_set_axis_names(x, 2, c("a", "b")): the number and the character vector can't be confused, so no name is needed.

The one thing to avoid is going halfway, for example naming the axis in the setters but not in the getters. That would feel random.

# Array slicing and extraction plan

## Recommendation

Use ordinary R subscripts for slicing and extraction:

```r
rray_slice(x, ...)
rray_slice_assign(x, ..., value)

rray_slice_axis(x, i, ..., axis)
rray_slice_assign_axis(x, i, ..., axis, value)

rray_slice_rows(x, i)
rray_slice_assign_rows(x, i, value)

rray_slice_columns(x, i)
rray_slice_assign_columns(x, i, value)

rray_extract(x, i)
rray_extract_assign(x, i, value)
```

`rray_slice()` performs dimension-preserving orthogonal selection across one
or more axes. It requires exactly one subscript per source axis, so `TRUE`
selects a whole axis. `rray_slice_axis()` performs the same operation on one
axis held in a variable, and `rray_slice_rows()` and `rray_slice_columns()`
are its first and second axis shortcuts. `rray_extract()` accepts flat
positions or coordinate points and always returns a one-dimensional array.

Keep subscripts separate from integer coordinate arrays:

| Property | Subscript | Coordinate array |
|---|---|---|
| Used by | `rray_slice()`, `rray_slice_axis()`, `rray_extract()` | `rray_index()`, `rray_index_axis()` |
| Meaning | A set of positions | One source coordinate per output point |
| Accepted forms | Integer, double, logical, character where defined, `NULL` | Bare integer vector or array |
| Negative values | Select the complement | Error |
| Zero | Ignored | Error |
| Shape | Does not connect positions across axes | Connects coordinates pointwise through broadcasting |

The function name determines the contract. The dimensions of `i` never turn a
slice subscript into a coordinate array. `rray_extract()` has a separate,
explicit matrix rule for coordinate points.

Do not add replacement functions. Every `_assign()` function returns a
modified copy of `x`. There are no `[` or `[[` methods because rray provides
functions rather than an array class.

## The indexing family

The complete family has five read operations:

| Operation | Function | Result shape |
|---|---|---|
| Orthogonal subscripts | `rray_slice(x, ...)` | One output axis per source axis |
| One-axis subscript | `rray_slice_axis(x, i, ..., axis)` | Source dimensions with one axis replaced |
| First or second axis subscript | `rray_slice_rows(x, i)`, `rray_slice_columns(x, i)` | Source dimensions with one axis replaced |
| One-axis coordinate array | `rray_index_axis(x, i, ..., axis)` | Source dimensions with one axis replaced |
| Full coordinate arrays | `rray_index(x, ...)` | Common coordinate dimensions |
----
#' Reduce an array along axes
#'
#' @description
#' - `rray_sum()` computes the sum along the specified `axes`.
#'
#' - `rray_prod()` computes the product along the specified `axes`.
#'
#' - `rray_mean()` computes the mean along the specified `axes`.
#'
#' - `rray_all()` checks if all values are `TRUE` along the specified `axes`.
#'
#' - `rray_any()` checks if any value is `TRUE` along the specified `axes`.
#'
#' - `rray_max()` computes the maximum along the specified `axes`.
#'
#' - `rray_min()` computes the minimum along the specified `axes`.
#'
#' @details
#' The dimensionality of `x` is retained in the result, with the reduced axes
#' collapsed to size 1.
#'
#' @section Sum:
#' Logicals are summed as integers. If an integer sum doesn't fit in an
#' integer, an error is thrown. Only the final sum is checked, and `NA` wins
#' over an overflow:
#'
#' ```r
#' x <- c(.Machine$integer.max, 1L, -1L)
#' rray_sum(x, 1L) # .Machine$integer.max
#'
#' x <- c(.Machine$integer.max, 1L, NA)
#' rray_sum(x, 1L) # NA
#' ```
#'
#' @section Product:
#' Logicals and integers are cast to double.
#'
#' When `NA` and `NaN` are both present, you get one of them, but which one
#' depends on the platform and the order of the values. Either way, `is.na()`
#' is `TRUE`. Integers can hit this too, since a product that overflows to
#' `Inf` becomes `NaN` when multiplied by `0`:
#'
#' ```r
#' rray_prod(c(NA, NaN), 1L) # NA or NaN
#'
#' x <- c(rep(.Machine$integer.max, 40L), 0L, NA)
#' rray_prod(x, 1L) # NA or NaN
#' ```
#'
#' @section Mean:
#' Logicals and integers are cast to double.
#'
#' When `NA` and `NaN` are both present, you get one of them, but which one
#' depends on the platform and the order of the values, like [mean()]. Either
#' way, `is.na()` is `TRUE`:
#'
#' ```r
#' rray_mean(c(NA, NaN), 1L) # NA or NaN
#' rray_mean(c(NaN, NA), 1L) # NA or NaN
#' ```
#'
#' @section Min / Max:
#' `rray_max()` and `rray_min()` keep the type of `x`. With nothing to reduce,
#' such as an axis of dimension 0, `rray_max()` returns the smallest value of
#' that type and `rray_min()` returns the largest:

# Require axes by name

## Goal

Move `axis` and `axes` behind `...` wherever a bare number could be mistaken
for data:

```r
# Before
rray_sum(x, 2)

# After
rray_sum(x, axes = 2)
```

`rray_add(x, 2)` and `rray_sum(x, 2)` look the same today but mean very
different things. Naming the axis removes that doubt.

## The rule

Require a name when a bare value could be mistaken for something else.

- `rray_sum(x, 2)`: the `2` could be data, so `axes` must be named.

- `rray_axis_names(x, 2)`: the function name says "axis", so no name is needed.

- `rray_rep(x, ..., times, axes)`: two numbers side by side, so both are named.
  This is already the case.

- `rray_slice_axis(x, i, ..., axis)`: `i` and `axis` are both numbers, so
  `axis` is named even though "axis" is in the function name. This is already
  the case.

## What changes

| Function | Before | After |
|---|---|---|
| `rray_sum()`, `rray_prod()`, `rray_mean()`, `rray_all()`, `rray_any()`, `rray_max()`, `rray_min()` | `(x, axes, ..., na_rm = FALSE)` | `(x, ..., axes, na_rm = FALSE)` |
| `rray_locate_max()`, `rray_locate_min()` | `(x, axis, ..., na_rm = FALSE)` | `(x, ..., axis, na_rm = FALSE)` |
| `rray_cumulative_all()`, `rray_cumulative_any()`, `rray_cumulative_max()`, `rray_cumulative_min()`, `rray_cumulative_prod()`, `rray_cumulative_sum()` | `(x, axis)` | `(x, ..., axis)` |
| `rray_reverse()` | `(x, axes)` | `(x, ..., axes)` |
| `rray_unstack()` | `(x, axis)` | `(x, ..., axis)` |

## What stays the same

- Functions with "axis" or "axes" in the name and only one number:
  `rray_axis_names()`, `rray_axis_title()`, `rray_set_axis_names()`,
  `rray_set_axis_title()`, `rray_insert_axes()`, `rray_remove_axes()`,
  `rray_permute_axes()`.

- Functions that already follow the pattern: `rray_move_axes()`, `rray_rep()`,
  `rray_rep_each()`, `rray_roll()`, `rray_roll_each()`, `rray_split()`,
  `rray_slice_axis()`, `rray_slice_assign_axis()`, `rray_combine()`,
  `rray_stack()`.

- Functions without an axis: setters like `rray_set_names()`, subscripts like
  `i` in `rray_extract()` and `rray_slice_rows()`, `dimensions` in
  `rray_broadcast()`, and every binary op like `rray_add(x, y)`.

- Old plans in `plans/`. They record past decisions and are not rewritten.

## Error

Use rlang's `check_dots_empty0()`, like `rray_rep()` and `rray_roll()` already
do. A positional axis then gives:

```
`...` must be empty.
✖ Problematic argument:
• ..1 = 2
ℹ Did you forget to name an argument?
```

No custom error.

## How to implement

Make one commit per function, in the order of the checklist below. Every
commit must pass `devtools::test()` and `devtools::check()` on its own, so a
commit changes the function and every caller of it at once.

For each function:

1. Move `axis` or `axes` behind `...` in the signature. Add
   `check_dots_empty0(...)` as the first line if the function doesn't already
   have it.

2. Add `@inheritParams rlang::args_dots_empty` to the roxygen block if it isn't
   already there.

3. Name the axis at every call site of the function:

   - Roxygen examples and prose in `R/`, including other functions' docs.
     For example, `R/cumulative.R` mentions `rray_sum(x, 1L)`.

   - Tests in `tests/testthat/`.

   - `README.Rmd` and `vignettes/`.

   - Test helpers that mirror the signature, such as
     `rray_sum_forced_fallback()` in `tests/testthat/helper-reduce-sum.R` and
     `rray_mean_forced_fallback()` in `tests/testthat/helper-reduce-mean.R`.
     Change their signature in the same commit as the function they mirror.

4. Add a test next to the function's other argument tests:

   ```r
   test_that("`axes` must be named", {
     expect_snapshot(rray_sum(1:3, 1), error = TRUE)
   })
   ```

   Use `axis` instead of `axes` in the test name where that is the argument.

5. Run `Rscript -e "devtools::document()"`, then
   `Rscript -e "devtools::build_readme()"` if `README.Rmd` changed.

6. Run `Rscript -e "testthat::snapshot_accept()"` only after reviewing the
   snapshot diff. Existing snapshots record the calls, so they change too.

7. Run `air format .` and `Rscript -e "devtools::test()"`.

8. Tick the function off in the checklist below in the same commit.

9. Commit with a one sentence message, such as
   ``Require `axes` to be named in `rray_sum()` ``.

All commits land in one pull request from `feature/dots`.
