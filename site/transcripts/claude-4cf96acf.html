I agree, and I think there is a clean rule behind your instinct.

The rule: if a function takes values and returns the same kind of value, it keeps names. If it takes values and returns a verdict about them, it drops names.

  • rray_add(): number, number → number. The result is a new value at the same labeled spot, so the names still describe it.

  • rray_and(): logical, logical → logical. Same shape of operation. A mask over rows a, b combined with another mask over rows a, b is still a mask over rows a, b.

  • rray_equal(): anything, anything → logical. The result answers a question about how two inputs relate. It isn't a new version of either one.

Why the split matters in practice. The plan errors when names conflict, and that is where the two groups really part ways:

  • With rray_equal(x, y), inputs whose names differ are a normal thing to compare. Erroring there would block an honest question like "are these two the same?". Dropping names avoids that.

  • With rray_and(x, y), two masks with different row names almost always means they are misaligned. An error there catches a real bug, the same way it does for rray_add().

Two caveats to weigh:

  1. The gain is smaller than it looks. Most masks come from comparisons, as in rray_and(rray_greater_than(x, 0), rray_less_than(x, 5)). Comparisons drop names, so rray_and() gets no names to keep. Keeping names only pays off when the logical inputs carry labels themselves, for example a stored is_valid matrix.

  2. The rule pulls rray_if_else() along with it. It returns values taken from true and false, so under this rule it should keep their names, and probably ignore the names on condition. Today the plan groups it with the functions that drop names on purpose. If you adopt the rule, it would be the odd one out.

My recommendation: adopt the rule and move rray_and(), rray_or(), and rray_xor() into the keep-and-check group with arithmetic. Then rewrite section 10 of plans/names-and-titles.md around the rule, so its reason for dropping names isn't "the result is a statement about the inputs", since that reason could apply to rray_and() too. Decide on rray_if_else() at the same time. Want me to update the plan that way?

41	
42	For each axis of the result:
43	
44	- An input has a say only if it has names on that axis and its dimension
45	  there is not broadcast. An axis of dimension 1 that stays 1 is not
46	  broadcast.
47

49	  has no say.

52	  holes: `c("r1", "")` and `c("r1", "r2")` disagree. `NA` agrees only with
53	  `NA`.
54	
55	- If they agree, the result has those names. If no input has a say, the axis
56	  has no names.

59	  together from every input, with `""` for unnamed inputs, as today.
60	
61	- The new axis of `rray_stack()` is not checked. Its names come from the names
62	  of `...`, as today.

64	## Titles rules
65	
66	Titles are the names on the dimnames list.
67	
68	- An empty title, or no titles at all, has no say.
69	
70	- Every other title on an axis must agree, including titles from inputs that
71	  broadcast on that axis or have no names there. A title labels the axis, not
72	  its positions, so it survives broadcasting.
73	
74	- Because all non-empty titles must agree, the title of an axis is that one
75	  agreed title, or `""` when nobody has one.
76	
77	- The result has a titles vector exactly when some input has one.
78	
79	- The combine axis of `rray_combine()` is checked like any other axis.
80	
81	- The new axis of `rray_stack()` gets the title `""`.
82	
83	- `rray_broadcast()` keeps every title of `x`, so it no longer depends on
84	  whether any broadcasting happened.

dim2_common <- function(dim_x, dim_y) {
  # find common dim for two arrays to be broadcast to
  ndim_x <- length(dim_x)

#' @importFrom rlang inject missing_arg
broadcast_array  <- function(x, dim, broadcast_scalars = TRUE) {
  if (!broadcast_scalars && length(x) == 1) {
    # quick exit: not broadcasting scalars; return them as vectors
    dim(x) <- NULL
    return(x)
  }

  current_dim <- dim(x) %||% length(x)
  current_dimnames <- dimnames(x)

  if (length(current_dim) < length(dim)) {
    # add dimensions of size 1 as necessary so we can broadcast those
    new_dim <- seq(length(current_dim) + 1, length(dim))
    current_dim[new_dim] <- 1
    dim(x) <- current_dim
    if (!is.null(current_dimnames)) {
      current_dimnames[new_dim] <- list(NULL)
      dimnames(x) <- current_dimnames
    }
  } else if (length(current_dim) > length(dim)) {
    stop_no_call(
      "Cannot broadcast array of shape [", paste(current_dim, collapse = ","), "] ",
      "to array of shape [", paste(dim, collapse = ","), "]:\n",
      "Desired shape has fewer dimensions than existing array."
    )
  }

  dim_to_broadcast <- which(current_dim != dim)

  if (length(dim_to_broadcast) == 0) {
    # quick exit: already has desired dim or just needed extra dims on the end
    return(x)
  }

  if (any(current_dim[dim_to_broadcast] != 1)) {
    stop_no_call(
      "Cannot broadcast array of shape [", paste(current_dim, collapse = ","), "] ",
      "to array of shape [", paste(dim, collapse = ","), "]:\n",
      "All dimensions must be 1 or equal."
    )
  }

  if (!is.null(current_dimnames)) {
    # the slice (below) should correctly preserve dimnames that are not broadcast,
    # but it will also duplicate dimnames that were broadcast --- which is probably
    # undesirable as those dimnames are no longer unique. So, drop those before
    # we do the broadcast (this can be much faster than dropping afterwards if
    # the broadcast dimensions are large)
    dimnames(x)[dim_to_broadcast] <- list(NULL)
  }

  # construct the indices used in a slice that will broadcast the array
  # e.g. if we want to broadcast x with dim c(2,1,2,4) to dim c(2,3,2,4), we
  # need to do the slice x[,c(1,1,1),,], which broadcasts the second dimension
  # to length 3
  # first, construct the list of missing arguments
  indices <- rep(list(missing_arg()), length(dim))
  # second, fill in the appropriate number of 1s in the dims we want to broadcast
  indices[dim_to_broadcast] <- lapply(dim[dim_to_broadcast], rep, x = 1L)

  # do the slice to broadcast the array
  inject(x[!!!indices, drop = FALSE])
}

Posterior has no names policy of its own. Every rvar operation passes the underlying draws arrays to base R and keeps whatever base R returns. It never checks names and never errors on a conflict. On top of that, a side effect of how posterior stores draws makes the rule worse than base R's: the first argument's names always win, even when it has none.

I read the source of posterior 1.7.0 from CRAN and ran about 45 cases against it.

How it works

An rvar stores its values in a base array, draws_of(x), with draws as an extra first axis. Ops.rvar() (R/rvar-math.R) does three things:

  1. Matches the number of chains and draws.

  2. Broadcasts both draws arrays with broadcast_array() (R/rvar-.R). On every broadcast axis it sets the names to NULL first, because repeated names would no longer be unique. The names on the dimnames list (what rray calls titles) are left alone.

  3. Calls the base R operator, f(draws_x, draws_y), and wraps the result.

All of the names behavior comes from step 3. In base R's relop.c and arithmetic.c, the result takes the whole dimnames attribute from x if x has one, otherwise from y. The choice covers the whole list, not one axis at a time.

The catch is that cleanup_rvar_draws() always gives the draws axis row names ("1", "2", ...). So every draws array has a dimnames attribute, and the "otherwise from y" branch never runs. In practice, the first argument always wins.

So a * b and b * a can give different names, and an unnamed first argument erases the second argument's names.

Other operations

  • rvar_ifelse() takes the whole names list from yes. The names on test and no are ignored, and an unnamed yes gives no names.

  • rbind() and cbind() go through abind(use.dnns = TRUE), so the last input wins on the other axes, for names and titles. That matches base rbind(). The new axis is pasted from argument names, with "" for unnamed inputs.

  • rbind(jan = v1, feb = v2) on named vectors drops the vector names entirely. make_at_least_2d() sets dim(), which drops them. Base R would keep v1's names, which is wrong in a different way: it silently mislabels feb when the order differs.

  • c() pastes names together, like x.r1 and y.a.

  • %**% takes row names and title from x, and column names and title from y. This is pinned by a test.

  • rfun(), rdo(), rvar_sum() drop all names.

  • Single-input operations keep everything: exp(), mean() over draws, slicing, t(), aperm(), drop(), rvar_apply() margins.

Is this deliberate?

Mostly no. The tests compare against new_rvar(x_array + y_array) using inputs that never disagree, so name conflicts are never tested. NEWS and the rvar vignette never mention how names combine. The only deliberate choices I found are:

  • dropping names on broadcast axes

  • the %**% rule

  • the c() and rbind() pasting

Everything else is base R plus the side effect of the draws axis names.

What this means for rray

  1. It agrees with our plan on two points. Posterior drops names on a broadcast axis and keeps titles across broadcasting, for the same reasons as rule 3 and the titles rules in plans/names-and-titles.md.

  2. It shows the bug the plan prevents. Mismatched names are silently resolved by argument order, and swapping the arguments changes the answer. rray today is already better, since it picks per axis rather than taking one input's whole list. Erroring on conflicts closes the rest of the gap.

  3. It offers no precedent for splitting comparisons from logical functions. Posterior treats arithmetic, comparison, and logical operators identically. Our split rests on the rule we adopted, with vctrs::vec_equal() as the outside precedent.

  4. A warning about representation. If an rray result ever goes through base R with an always-present dimnames attribute, the same side effect could appear. rray computes names itself, so it's not a risk today.

  5. Worth keeping if rray adds matrix multiplication: posterior's %**% rule (rows and title from x, columns and title from y) is a reasonable default.
