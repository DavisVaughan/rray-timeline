On 2026-10-01 a `one-add.h` shared by `rray_add()` and `rray_sum()` was built and then abandoned (branch `feature/one-add` deleted). Kernels for arithmetic and their reducers stay local to each `.c` file, even with overlap.

**Why:** The reducer's job differs from the elementwise op. Sum's logical kernel mixes an int accumulator with logical input, `na_rm` exists only for the reducer, and sharing forced `error_call` plumbing through every `RRAY_REDUCE` caller. The earlier `one-logical.h` / `one-extremum.h` split (#102) was also reverted on branch `feature/revert-one`, so no `one-*.h` headers exist. See [[feedback_no_int_helpers_for_logical]].

Update 2026-10-01: the user then asked to keep `src/one-extremum.h` (branch `feature/extremum-one`, off `main`), split into `// Elementwise` (`rray_pmax_*_one`) and `// Reduce` (`rray_max_*_one`) sections. A reduce helper calls its elementwise twin only when they are exactly the same.

**How to apply:** Don't propose `one-multiply.h` and similar for arithmetic/reducer pairs. Pending idea from that session: switch `rray_sum()` double and complex kernels to plain `+` (4x faster across rows), since base R leaves NA vs NaN unspecified for arithmetic.

// --------------------------------------------------------------------------
// Elementwise

// Logical `NA` is `INT_MIN`, so it is never false
// - `x = 1`, `y = 1`: returns `1` (`any_false = false`, `equal = true`).
// - `x = 1`, `y = 0`: returns `0` (`any_false = true`).
// - `x = 1`, `y = NA`: returns `NA` (`any_false = false`, `equal = false`).
// - `x = 0`, `y = NA`: returns `0` (`any_false = true`).
// - `x = NA`, `y = NA`: returns `NA` (`any_false = false`, `equal = true`).
static inline int rray_and_lgl_one(int x, int y) {
  const bool any_false = !x || !y;
  const bool equal = x == y;
  return !any_false * (equal * x + !equal * r_globals.na_lgl);
}

// Logical `NA` is `INT_MIN`, so it is never `1`
// - `x = 1`, `y = 0`: returns `1` (`any_true = true`).
// - `x = 1`, `y = NA`: returns `1` (`any_true = true`).
// - `x = 0`, `y = 0`: returns `0` (`any_true = false`, `equal = true`).
// - `x = 0`, `y = NA`: returns `NA` (`any_true = false`, `equal = false`).
// - `x = NA`, `y = NA`: returns `NA` (`any_true = false`, `equal = true`).
static inline int rray_or_lgl_one(int x, int y) {
  const bool any_true = (x == 1) || (y == 1);
  const bool equal = x == y;
  return any_true + !any_true * (equal * x + !equal * r_globals.na_lgl);
}

// Bitwise `|` improves efficiency here
// - `x = 1`, `y = 0`: returns `1` (`elt = 1`, `missing = false`).
// - `x = 1`, `y = 1`: returns `0` (`elt = 0`, `missing = false`).
// - `x = 1`, `y = NA`: returns `NA` (`elt = 1`, `missing = true`).
// - `x = NA`, `y = NA`: returns `NA` (`elt = 0`, `missing = true`).
static inline int rray_xor_lgl_one(int x, int y) {
  const bool missing =
    bool_bitwise_or(rray_lgl_is_missing(x), rray_lgl_is_missing(y));
  const int elt = x != y;
  return missing ? r_globals.na_lgl : elt;
}
