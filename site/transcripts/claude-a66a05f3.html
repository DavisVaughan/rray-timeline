# Dropping the ALTREP wrapper

`r_wrap()` (`src/wrapper.c`) has a memory safety bug: a read-only data pointer
taken before a writable request can dangle. Fixing it properly costs a copy on
the first outside read, plus a lot of tricky code to keep sound. The previous
version of this plan (commit `4565791`) describes the bug and that fix in
detail.

This plan removes the wrapper instead. The wrapper exists for two reasons:

1. `vec_as_array()` wraps every plain vector input, so rray can treat it as a
   1D array without copying it.

2. The attribute setters (`rray_set_dimensions()` and friends) return a
   wrapper, so changing attributes does not copy the data.

Reason 1 goes away if rray reads a plain vector as a 1D array natively, with
no object in between. Reason 2 goes away if the setters copy, the way base
R's `dim<-` copies shared data.

The work is three checklists, done one pull request at a time, in order:

1. Low-level helpers that natively understand plain vectors.

2. Functions moved off `arg_as_array()` and `vec_as_array()`.

3. Setters that copy, then deleting the wrapper.

Every pull request is green on its own. Until the last one, `arg_as_array()`
still wraps, and a wrapper has real dimensions, so native helpers and
unmigrated functions work together at every step.

---

# Part 1: The model

## A plain vector is a 1D array

Everywhere in rray, a vector without a `dim` attribute reads as a 1D array:

|                | array               | plain vector                  |
|----------------|---------------------|-------------------------------|
| dimensions     | `dim(x)`            | `length(x)`                   |
| dimensionality | `length(dim(x))`    | `1`                           |
| names          | `dimnames(x)`       | `list(names(x))`, or `NULL`   |
| titles         | `names(dimnames(x))`| `NULL`                        |
| data           | `x`                 | `x`                           |

This is exactly what `vec_as_array()` produces today, so no user-visible
reading changes:

```r
x <- c(a = 1, b = 2)
rray_dimensions(x)
#> [1] 2
rray_names(x)
#> [[1]]
#> [1] "a" "b"
```

## rray returns arrays

Functions that allocate their output already set `dim` on it from the
computed dimensions, so they keep returning arrays when given a plain vector.

The exceptions are the paths that return an input unchanged. Part 5 lists
every one of them, and gives each a fix so it returns a 1D array too. rray
always returns arrays.

## `check_vector()`

`arg_as_array()` does two things: it rejects scalar types (with
`stop_scalar_input()`), and it calls `vec_as_array()`. `check_vector()` takes
over the first:

```c
void check_vector(r_obj* x, struct rray_arg* arg, struct r_lazy error_call) {
  if (rray_typeof(x) == RRAY_TYPE_scalar) {
    stop_scalar_input(x, arg, error_call);
  }
}
```

It goes in `src/utils.c`, next to `check_unclassed()`, and every
migrated function calls it right after `check_unclassed()`:

```c
check_unclassed(x, arg, error_call);
check_vector(x, arg, error_call);
```

rray supports list arrays, and `rray_typeof()` reports a list as
`RRAY_TYPE_list`, so lists pass `check_vector()`, the same as they pass
`arg_as_array()` today.

## Protection

`r_dim()` and `r_dim_names()` never allocate. Much of the code relies on
that and leaves their result unprotected:

```c
r_obj* x_dimensions = r_dim(x);
const int* v_x_dimensions = r_int_cbegin(x_dimensions);
```

`rray_dimensions()` and `rray_names()` allocate for a plain vector. So every
`r_dim(x)` that becomes `rray_dimensions(x)` must be `KEEP()`ed, and the
function's `FREE()` count goes up. This is the main mechanical risk in
Checklist 2, and the protection pass in Part 6 is how it gets checked.

## `r_dim()` calls that stay

Some `r_dim()` calls ask "does this object have a `dim` attribute?", not "what
are its dimensions?". These must keep `r_dim()`:

- Subscript shape checks: `rray_as_extract_subscript()`,
  `rray_as_extract_mask()`, `rray_as_extract_points()`
  (`src/extract-subscript.c`) and `rray_as_slice_subscript()`
  (`src/slice-subscript.c`). A numeric matrix means points and a numeric
  vector means locations, so a missing `dim` is meaningful here.

- Reads of an output rray just allocated and gave a `dim`, like `r_dim(out)`
  in `RRAY_EXTRACT_ASSIGN_POINTS_LOOP()`.

# Part 2: Checklist 1, native helpers

One pull request each. Each helper keeps its signature and its own
`check_unclassed()` call, since most are also FFI entry points. They replace
`arg_as_array()` with `check_vector()`.

Callers do not change in these pull requests: they still pass arrays
(often wrappers), and the array path of each helper behaves as it does
today. Each pull request adds tests for the plain vector path through the
exported R function.

- [ ] **`check_vector()`.** Add it to `src/utils.c` and `src/utils.h`. Make
  `arg_as_array()` call it, so the error stays in one place. No behavior
  change.

- [ ] **`rray_clone_array()`** (`src/clone.c`, `src/clone.h`). Returns a
  shallow duplicate of `x` (`r_clone()`, which copies the data and keeps
  every attribute, as `r_wrap()` does today). For a plain vector, it also
  does what `vec_as_array()` does: set `dim` to `length(x)`, and move
  `names` into `dimnames`. Used by the Part 5 early returns and by every
  setter in Checklist 3. Test it through a small FFI test helper, since
  nothing calls it yet.

- [ ] **`rray_dimensions()`** (`src/dimensions.c`). Return `r_dim(x)` when it
  is not `r_null`, else `r_int(r_ssize_as_integer(r_length(x)))`. Long
  vectors hit the same internal error they hit in `vec_as_array()` today.

  Callers already treat the result as possibly allocated, because it
  currently comes off a wrapper that is about to be freed. Check each one
  anyway: `rray_dimension()`, `rray_dimensionality()`, `rray_broadcast()`,
  `rray_dimensions_common_opts()`, `rray_broadcast_names_fill()`,
  `rray_reduce_names()`, `rray_set_names()`, `rray_split()`,
  `rray_permute_axes()`, `rray_locate()`, `rray_reduce()`,
  `rray_insert_axes()`, `rray_remove_axes()`,
  `rray_expand_dimensionality()`.

- [ ] **`rray_dimensionality()`** (`src/dimensionality.c`). Return `1` for a
  plain vector without allocating, else `r_length(r_dim(x))`. It is called
  per element in `list_max_dimensionality()`.

- [ ] **`rray_size()`** (`src/size.c`). Already `r_length(x)`. Swap
  `arg_as_array()` for `check_vector()`.

- [ ] **`rray_names()`** (`src/names.c`). Return `r_dim_names(x)` when
  `x` has a `dim`. For a plain vector, return `r_null` when `names(x)` is
  `r_null`, else a fresh `list(names(x))`.

  Check each caller protects the result before its next allocation:
  `rray_axis_names()`, `rray_set_axis_names()`, `rray_titles()`,
  `rray_broadcast_names_fill()`, `rray_reduce_names()`.

- [ ] **`rray_axis_names()`** (`src/names.c`). For a plain vector, after the
  axis check, return `names(x)` directly instead of going through the list.
  This saves the allocation on `rray_row_names()` of a vector.

- [ ] **`rray_titles()`** and **`rray_axis_title()`** (`src/titles.c`). Return
  `r_null` for a plain vector without calling `rray_names()`. A plain vector
  never has titles.

These need no change of their own, and become native once the helpers above
land. Tick them off with a test each:

- [ ] `rray_dimensions_common()`, `rray_dimensions_common_opts()`,
  `list_max_dimensionality()`.

- [ ] `rray_broadcast_names()`, `rray_broadcast_names2()`,
  `rray_broadcast_names_common()`, `rray_reduce_names()`.

#include "wrapper.h"

#include <R_ext/Altrep.h>

#include "clone.h"

#include "decl/wrapper-decl.h"

static char* package = "rray";

// Wrap an R object in a lightweight ALTREP wrapper
//
// Useful when only modifying the attributes of an object,
// without touching the underlying data.
//
// - Read only accesses to the data are "passed through" to the wrapped object
// - Writable access forces a shallow duplication of the wrapped object if it
//   EVER looks shared, which happens if we are wrapping a basic R object
//   supplied from the R side by a user, or if we rewrap a wrapper's underlying
//   data (because the original wrapper also shares it).
r_obj* r_wrap(r_obj* x) {
  R_altrep_class_t cls = wrapper_class(r_typeof(x));

  // If `x` is a wrapper, unwrap it to gain access to the underlying data. This
  // is what we wrap and bump the reference count of. This avoids a
  // proliferation of wrappers. We manage writable access to the underlying data
  // by always cloning it before giving out a writable handle if it is ever
  // `MAYBE_SHARED()` (i.e. a ref count >1), meaning that we aren't the sole
  // owner of it at that time.
  r_obj* data = is_wrapper(x) ? wrapper_readonly(x) : x;

  // Reference count on `data` is bumped when we wrap it here.
  // It now looks at least "referenced", but not necessarily "shared".
  r_obj* out = KEEP(R_new_altrep(cls, data, r_null));

  // Creates a fresh attribute pairlist!
  // Note that we always use `x` here, not `data`.
  r_attrib_clone_from(out, x);

  FREE(1);
  return out;
}

Yes, it would fix the bug, but only if it covers all writes, and the price is that rray's results can no longer be modified.

Why it fixes the bug

A stale pointer only happens when wrapper_writable() swaps out data1. If nothing ever swaps it, data1 stays the same vector for the wrapper's whole life. The wrapper keeps that vector alive, so any read-only pointer into it stays valid. Rewrapping and shallow duplicates share data1, which is also fine when nobody writes.

There is a catch. Dataptr is not the only caller of wrapper_writable(). The character and list Set_elt methods call it too (src/wrapper.c, the Set_elt section). This still dangles:

const r_obj* const* p = r_chr_cbegin(w);
SET_STRING_ELT(w, 0, v); // swaps data1
p[0];                    // points into the old vector

So "never writable" has to mean the writable Dataptr aborts for every type and Set_elt aborts as well. For strings and lists you can just drop Set_elt, because R's defaults already raise an error (altstring_Set_elt_default() in src/main/altrep.c).

Why it doesn't help in practice

A wrapper reaches the user, through rray_set_dimensions() and friends. R asks for writable pointers all the time, even on objects it owns:

  • Modifying in place. In y <- rray_set_dimensions(x, 2:3); y[1] <- 0, y is not shared, so R skips the duplicate. It then calls REAL(y) on the wrapper (src/main/subassign.c:736), and that errors. Changing the Duplicate method doesn't help, because R never calls it here.

  • Reading with REAL(). A lot of base R and package C code reads through REAL() or INTEGER() instead of the _RO versions. Every one of those calls would error on a wrapper.

So you would swap a rare memory bug for a common, visible error. That is safer, but it isn't a wrapper users can live with. Making writes work again means replacing data1 at some point, and doing that safely is what base R's lock does: copy before handing out the first pointer, then never swap. That was the costly design in the earlier plan.

That's why the current plan in plans/wrap.md removes the wrapper. If the data is never shared, nothing has to stop writes.
