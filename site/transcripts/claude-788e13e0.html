static r_obj* rray_slice_axis_names(
  r_obj* x_axis_names,
  bool identity,
  const r_ssize* v_locations,
  int dimension
) {
  if (identity) {
    return x_axis_names;
  }

  r_obj* const* v_x_axis_names = r_chr_cbegin(x_axis_names);

  r_obj* out = KEEP(r_alloc_character(dimension));

  for (int i = 0; i < dimension; ++i) {
    const r_ssize location = v_locations[i];
    r_chr_poke(
      out,
      i,
      location == RRAY_SLICE_MISSING ? r_globals.na_str
                                     : v_x_axis_names[location]
    );
  }

  FREE(1);
  return out;
}

Yes. vctrs fills the name with "" when the index is NA. rray4 fills it with NA (src/slice.c:344), which is what base R does.

In vctrs, slice_names() calls chr_names_slice(), and that function uses r_strs.empty as the fill value instead of r_globals.na_str (vctrs/src/slice.c:161). This also applies to the row names of a matrix passed to vec_slice().

x <- c(a = 1, b = 2)
names(vctrs::vec_slice(x, c(1, NA)))
#> [1] "a" ""
names(x[c(1, NA)])
#> [1] "a" NA

m <- matrix(1:4, 2, dimnames = list(c("a", "b"), NULL))
rownames(vctrs::vec_slice(m, c(1, NA)))
#> [1] "a" ""
rownames(m[c(1, NA), , drop = FALSE])
#> [1] "a" NA

I'd switch to r_strs.empty to match vctrs. vctrs treats an NA name as a missing name and repairs it to "" anyway (vctrs/src/names.c:209). Keeping NA would only make sense if you want rray_slice() to match base [. It's a one-token change plus updated tests. Should I make it?

#' @description
#' `rray_slice()` selects positions along each axis of `x`. The result always
#' has the same dimensionality as `x`.
#'
#' @details
#' `NA` in a subscript gives missing values in the result. For raw arrays the

#'
#' Unlike `[`, an empty argument does not select a whole axis. Use `TRUE`
#' instead, so that every axis is provided explicitly:
#'
#' ```r
#' x <- array(1:24, c(2L, 3L, 4L))
#'
#' # Base R
#' x[1, , , drop = FALSE]
#'
#' # rray
#' rray_slice(x, 1, TRUE, TRUE)
#' ```
#'
#' @param x An array.
#'

#'   subscript is one of:
#'

#'
#'   - A logical vector the size of the axis. `TRUE` selects a position.
#'
#'   - An integer or double vector of locations. Negative values drop
#'     positions, zero is ignored, and duplicates repeat positions.
#'

#'     first match is used when names are duplicated.
#'
#'   - `NULL`, to select nothing.
#'
#' @returns
#' An array with the same type and dimensionality as `x`. The dimension of each
#' axis is the number of positions selected on it. The names of each axis are
#' selected along with the values.
#'

#' @examples
#' x <- array(1:24, c(2L, 3L, 4L))
#'

Yes, it's required. Without it, rray_slice_start() can read past the end of memory when the result is empty.

  • Where the offsets live: every non-identity axis gets its offsets from one shared raw buffer. Each axis takes v_dimensions[axis] slots, one after another (src/slice.c:109-122).

  • What goes wrong: if a non-identity axis selects nothing (NULL, integer(), FALSE), it gets zero slots. Its v_offsets then points either at the next axis's slots or just past the end of the buffer. v_offsets[0] reads that. In the second case, for example rray_slice(x, 1L, NULL), the read is out of bounds, which is undefined behaviour in C.

  • Why returning 0 is safe: rray_slice() has no earlier exit for an empty result. With size == 0, the while (run_start != size) loop in RRAY_SLICE_ITERATE never runs, so start is never used. The guard only prevents the bad read. The value it returns doesn't matter.

Only a non-identity axis with dimension 0 needs the guard, but any such axis makes size 0, so size == 0 covers every case. An identity axis with dimension 0 is fine on its own, since its v_offsets is never read.
