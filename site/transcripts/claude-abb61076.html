     2	
     3	## Recommendation
     4	
     5	Change `rray_rep()` to repeat one or more axes, with one `times` per axis:
     6	
     7	```r
     8	rray_rep(x, ..., times, axes)
     9	rray_rep_each(x, ..., times, axis)
    10	```
    11	
    12	`rray_rep_each()` does not change.
    13	
    14	- `rray_rep()` repeats whole axes. `times` is size 1, used for every axis in
    15	  `axes`, or the size of `axes`, with `times[[i]]` used for `axes[[i]]`. This
    16	  is NumPy's `np.tile()` with explicit axes.
    17	
    18	- `rray_rep_each()` repeats each position along one axis. `times` is size 1 or
    19	  the dimension of `axis`.
    20	
    21	This makes the rep pair match the roll pair in `plans/roll.md` exactly:
    22	
    23	| Every lane together | Each position on its own |
    24	|---|---|
    25	| `rray_rep(x, ..., times, axes)` | `rray_rep_each(x, ..., times, axis)` |
    26	| `rray_roll(x, ..., n, axes)` | `rray_roll_each(x, ..., n, axis)` |
    27	
    28	The left column takes `axes` and one value per axis. The right column takes one
    29	`axis` and one value per position or lane.
    30	
    31	This is a breaking change to an exported function. `axis` is renamed to `axes`,
    32	with no deprecation path. An old call such as `rray_rep(x, times = 2, axis = 1)`
    33	now fails in `check_dots_empty0()`, since `axis` lands in the dots.
    34	
    35	## Why multiple axes are well defined
    36	
    37	Repeating along axis 1 and then axis 2 gives the same result as the other order.
    38	Every output position has exactly one source position:
    39	
    40	```text
    41	out[i1, ..., iD] = x[i1 mod d1, ..., iD mod dD]    (zero-based)
    42	```
    43	
    44	So one `times` per axis has a single meaning, the names rule stays the same,
    45	and there is no ordering question.
    46	
    47	## `rray_rep()`
    48	
    49	### Arguments
    50	
    51	- `x`: an array or bare vector.
    52	
    53	- `...`: must be empty. It forces `times` and `axes` to be named.
    54	
    55	- `times`: a bare integer vector of values greater than or equal to 0, size 1
    56	  or the size of `axes`. Validated with `arg_as_non_negative_bare_integer()`, as
    57	  today.
    58	
    59	- `axes`: a bare integer vector of axes. Required, with no default. Any order.
    60	  An axis can't appear twice. `integer()` is allowed and repeats nothing.
    61	  Validated with `arg_as_axes_unsorted()`, like `from` and `to` in
    62	  `rray_move_axes()` and `axes` in `rray_roll()`.
    63	
    64	The result has the type and dimensionality of `x`. Each axis in `axes` has its
    65	dimension multiplied by its `times`. Every other axis keeps its dimension.
    66

r_obj* arg_as_axes(
  r_obj* axes,
  int dimensionality,
  struct rray_arg* arg,
  struct r_lazy error_call
) {
  axes = KEEP(arg_as_bare_integer(axes, arg, error_call));
  check_axes(axes, dimensionality, arg, error_call);
  FREE(1);
  return axes;
}

void check_axes(
  r_obj* axes,
  int dimensionality,
  struct rray_arg* arg,
  struct r_lazy error_call
) {
  const r_ssize axes_size = r_length(axes);

  const int* v_axes = r_int_cbegin(axes);

  for (r_ssize i = 0; i < axes_size; ++i) {
    const int axis = v_axes[i];

    if (axis == r_globals.na_int) {
      r_abort_lazy_call(
        error_call,
        "%s must not contain missing values.",
        rray_arg_format(arg)
      );
    }

    if (axis < 1) {
      r_abort_lazy_call(
        error_call,
        "%s must contain values greater than or equal to 1, not %d.",
        rray_arg_format(arg),
        axis
      );
    }

    if (axis > dimensionality) {
      r_abort_lazy_call(
        error_call,
        "%s must contain values less than or equal to the "
        "dimensionality of %d, not %d.",
        rray_arg_format(arg),
        dimensionality,
        axis
      );
    }

    if (i > 0 && axis <= v_axes[i - 1]) {
      r_abort_lazy_call(
        error_call,
        "%s must be in strictly increasing order.",
        rray_arg_format(arg)
      );
    }
  }
}

        "%s must contain values less than or equal to the "

        rray_arg_format(arg),
        dimensionality,

    }

  }

  FREE(1);
  return axes;
}

## `rray_rep_each()`

No change in behavior. It keeps a single `axis`, for two reasons:

- A varying `times` across several axes would need a list with one vector per
  axis. That is a different argument shape from every other `times` in the
  package.

- NumPy's `np.repeat()` also takes one axis.

Julia's `repeat(x; inner = (2, 2))` does allow a uniform count per axis. The one
common use is upsampling, like turning each pixel into a 2x2 block. Two calls to
`rray_rep_each()` do the same thing.

Its C code does change shape, since it no longer shares an implementation with
`rray_rep()`. See below.

## Equivalences

These describe the function exactly and make good property tests.

Repeating several axes is repeating them one at a time, in any order:

```r
rray_rep(x, times = c(2, 3), axes = c(1, 3))
rray_rep(rray_rep(x, times = 2, axes = 1), times = 3, axes = 3)
rray_rep(rray_rep(x, times = 3, axes = 3), times = 2, axes = 1)
```

Repeating one axis is a slice of that axis, names included:

```r
rray_rep(x, times = t, axes = a)
rray_slice_axis(x, rep(seq_len(d), times = t), axis = a)
```

### The fill

The fill has two steps.

#### Step 1: the first axis, read from `x`

The first axis in `axes` is repeated straight from `x` into the start of `out`

Total work is at most about twice the size of `out`, since every in-place step
at least doubles the data already written.

#### Types

`rray_rep_expand()` switches on `r_typeof(out)` to seven cores, like
`rray_rep_fill_uniform()`. Each core is one macro call:

- `RRAY_REP_EXPAND_ATOMIC(CTYPE, DEREF)` for logical, integer, double, complex,
  and raw, with the loop above.

- `RRAY_REP_EXPAND_BARRIER(CONST_DEREF, POKE)` for character and list. It reads
  from `CONST_DEREF(out)` and writes with `POKE()` at the matching offset.

Both copy element by element in a loop, like every other fill in `src/rep.c`.
No `r_memcpy()`.

`rray_rep_fill()` is the driver that runs step 1 and then calls
`rray_rep_expand()` once per remaining axis.
