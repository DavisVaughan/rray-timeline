     1	# Multi-axis repeat plan
     2	
     3	## Recommendation
     4	
     5	Change `rray_rep()` to repeat one or more axes, with one `times` per axis:
     6	
     7	```r
     8	rray_rep(x, ..., times, axes)
     9	rray_rep_each(x, ..., times, axis)
    10	```
    11	
    12	`rray_rep_each()` does not change.
    13	
    14	- `rray_rep()` repeats whole axes. `times` is size 1, used for every axis in
    15	  `axes`, or the size of `axes`, with `times[[i]]` used for `axes[[i]]`. This
    16	  is NumPy's `np.tile()` with explicit axes.
    17	
    18	- `rray_rep_each()` repeats each position along one axis. `times` is size 1 or
    19	  the dimension of `axis`.
    20	
    21	This makes the rep pair match the roll pair exactly:
    22	
    23	| Every lane together | Each position on its own |
    24	|---|---|
    25	| `rray_rep(x, ..., times, axes)` | `rray_rep_each(x, ..., times, axis)` |
    26	| `rray_roll(x, ..., n, axes)` | `rray_roll_each(x, ..., n, axis)` |
    27	
    28	The left column takes `axes` and one value per axis. The right column takes one
    29	`axis` and one value per position or lane.
    30	
    31	This is a breaking change to an exported function. `axis` is renamed to `axes`,
    32	with no deprecation path. An old call such as `rray_rep(x, times = 2, axis = 1)`
    33	now fails in `check_dots_empty0()`, since `axis` lands in the dots.
    34	
    35	## Why multiple axes are well defined
    36	
    37	Repeating along axis 1 and then axis 2 gives the same result as the other order.
    38	Every output position has exactly one source position:
    39	
    40	```text
    41	out[i1, ..., iD] = x[i1 mod d1, ..., iD mod dD]    (zero-based)
    42	```
    43	
    44	So one `times` per axis has a single meaning, the names rule stays the same,
    45	and there is no ordering question.
    46	
    47	## `rray_rep()`
    48	
    49	### Arguments
    50	
    51	- `x`: an array or bare vector.
    52	
    53	- `...`: must be empty. It forces `times` and `axes` to be named.
    54	
    55	- `times`: a bare integer vector of values greater than or equal to 0, size 1
    56	  or the size of `axes`. Validated with `arg_as_non_negative_bare_integer()`, as
    57	  today.
    58	
    59	- `axes`: a bare integer vector of axes. Required, with no default. Must be in
    60	  strictly increasing order, since the order does not change the result.
    61	  `integer()` is allowed and repeats nothing. Validated with `arg_as_axes()`,
    62	  like `axes` in `rray_roll()`, `rray_remove_axes()`, and the reducers.
    63	
    64	The result has the type and dimensionality of `x`. Each axis in `axes` has its
    65	dimension multiplied by its `times`. Every other axis keeps its dimension.
    66	
    67	### Worked examples
    68	
    69	```r
    70	x <- matrix(1:4, nrow = 2, dimnames = list(c("r1", "r2"), c("a", "b")))
    71	
    72	x
    73	#    a b
    74	# r1 1 3
    75	# r2 2 4
    76	```
    77	
    78	One axis, as today:
    79	
    80	```r
    81	rray_rep(x, times = 2, axes = 2)
    82	#    a b a b
    83	# r1 1 3 1 3
    84	# r2 2 4 2 4
    85	```
    86	
    87	Both axes with a size 1 `times`:
    88	
    89	```r
    90	rray_rep(x, times = 2, axes = c(1, 2))
    91	#    a b a b
    92	# r1 1 3 1 3
    93	# r2 2 4 2 4
    94	# r1 1 3 1 3
    95	# r2 2 4 2 4
    96	```
    97	
    98	One `times` per axis, with `times[[i]]` used for `axes[[i]]`:
    99	
   100	```r
   101	rray_rep(x, times = c(2, 3), axes = c(1, 2))
   102	#    a b a b a b
   103	# r1 1 3 1 3 1 3
   104	# r2 2 4 2 4 2 4
   105	# r1 1 3 1 3 1 3
   106	# r2 2 4 2 4 2 4
   107	```
   108	
   109	A `times` of 0 gives a zero dimension on that axis. The other axes still
   110	repeat:
   111	
   112	```r
   113	out <- rray_rep(x, times = c(2, 0), axes = c(1, 2))
   114	
   115	dim(out)
   116	# [1] 4 0
   117	
   118	rray_names(out)
   119	# [[1]]
   120	# [1] "r1" "r2" "r1" "r2"
   121	#
   122	# [[2]]
   123	# NULL
   124	```
   125	
   126	Three dimensions, repeating the first and last axes:
   127	
   128	```r
   129	y <- array(1:8, c(2, 2, 2))
   130	
   131	out <- rray_rep(y, times = 2, axes = c(1, 3))
   132	
   133	dim(out)
   134	# [1] 4 2 4
   135	
   136	out[, , 1]
   137	#      [,1] [,2]
   138	# [1,]    1    3
   139	# [2,]    2    4
   140	# [3,]    1    3
   141	# [4,]    2    4
   142

   147	# [3,]    1    3
   148	# [4,]    2    4
   149	```
   150	
   151	Nothing repeats. Each of these gives a new array identical to `x`, names
   152	included:
   153	
   154	```r
   155	rray_rep(x, times = 1, axes = c(1, 2))
   156	rray_rep(x, times = 2, axes = integer())
   157	rray_rep(x, times = integer(), axes = integer())
   158	```
   159	
   160	### Names
   161	
   162	Each axis in `axes` repeats its own names `times` times, duplicates and all.
   163	Every other axis keeps its names untouched. This is today's rule applied once
   164	per axis, and is exactly what `rray_slice_axis()` does with the same locations.
   165	
   166	As today, names on the `dimnames` list itself are not kept. `rray_slice_axis()`
   167	drops them too, so that is a separate question for all of rray4.
   168	
   169	### Relationship to NumPy
   170	
   171	| NumPy | rray4 |
   172	|---|---|
   173	| `np.tile(x, (2, 1))` | `rray_rep(x, times = 2, axes = 1)` |
   174	| `np.tile(x, (2, 3))` | `rray_rep(x, times = c(2, 3), axes = c(1, 2))` |
   175	| `np.tile(x, 2)` on a matrix | `rray_rep(x, times = 2, axes = 2)` |
   176	| `np.tile(x, (2, 1, 1))` on a matrix | Not supported. Use `rray_insert_axes()` first |
   177	
   178	`np.tile()` lines `reps` up with the trailing axes, and adds new leading axes
   179	when `reps` is longer than the dimensionality. rray4 names every axis
   180	explicitly and never adds axes.
   181	
   182	### Errors
   183

   186	
   187	rray_rep(x, times = 2, axes = c(1, 1))

#' Roll an array
#'
#' @description
#' - `rray_roll()` rolls the elements of `x` along one or more `axes`, with one
#'   roll per axis. Everything along an axis moves by the same amount.
#'
#' - `rray_roll_each()` rolls the elements of `x` along a single `axis`, with
#'   a separate roll for each row, column, and so on. For example, with a
#'   matrix and `axis = 2`, each row can move by a different amount.
#'
#' An element pushed off one end circles back on the other.
#'
#' @details
#' A positive `n` moves elements toward the end of the axis, and a negative `n`
#' moves them toward the start. Rolls circle around, so an `n` of 7 along an
#' axis with dimension 5 is the same as an `n` of 2. An `n` of 0, or any
#' multiple of the dimension, leaves the axis unchanged.
#'
#' @section Roll:
#' Rolling an axis with a uniform `n` can be thought of as a carefully crafted
#' [rray_slice()]. Along an axis with dimension `d`, position `i` of the result
#' comes from position `(i - 1 - n) %% d + 1` of `x`:
#'
#' ```r
#' x <- c(a = 1L, b = 2L, c = 3L, d = 4L, e = 5L)
#'
#' n <- 2L
#' d <- length(x)
#' i <- seq_len(d)
#'
#' (i - 1L - n) %% d + 1L
#' #> [1] 4 5 1 2 3
#'
#' rray_roll(x, n = n, axes = 1)
#' #> d e a b c
#' #> 4 5 1 2 3
#'
#' rray_slice_axis(x, c(4, 5, 1, 2, 3), axis = 1)
#' #> d e a b c
#' #> 4 5 1 2 3
#' ```
#'
#' Rolling several axes at once is one `rray_slice()`, with these locations on
#' each rolled axis and `TRUE` on the rest.
#'
#' Since a uniform roll is a slice, names on a rolled axis move with the data,
#' just like they do in `rray_slice()`. Every other axis keeps its names
#' untouched.
#'
#' @section Roll each:
#' `rray_roll_each()` rolls along a single `axis`, but each row, column, and so
#' on can move by its own amount. That is why `n` is an array rather than a
#' vector. It is broadcast to the dimensions of `x` with `axis` set to 1, so it
#' holds one `n` for every row, column, and so on that gets rolled.
#'
#' Variable rolling can be mimicked with the more flexible indexing of
#' [rray_index()]. Along `axis`, the coordinates come from the same
#' `(i - 1 - n) %% d + 1` formula as `rray_roll()`, with a different `n` for
#' each row, column, and so on. Along every other axis, the coordinates are
#' just the positions themselves.
#'

Why the slice versions lose:

  • A slice copies element by element, looking up one location for each output element along axis 1. The current fills copy whole stretches of x at a time, which is faster when those stretches are long. That is why the slice versions are 10 to 30% slower on multi-axis repeats, on axis 1 of a square matrix, and on large times.
  • On 1D input, the location vector is as long as the output. Building it is cheap (about 0.2ms). Most of the time goes inside rray_slice(): on the 1D int case, 4.2ms of the 4.4ms total. That covers checking each of the 3e6 locations, scanning them again for missing values, and the element-by-element copy. It also costs 11.5MB of extra memory, which is 38% more for doubles and 75% more for integers.

Why the slice versions win: the current fills copy one stretch of x at a time, times times over. When a stretch is 1 or 2 elements long, the loop bookkeeping costs more than the copying. rray_rep_each() along axis 1 always has stretches of 1 element, which is why it takes 3.8ms on a 1000x1000 matrix while axis 2 takes 1.6ms. The old code had the same weakness (3.81ms before this change), so it isn't new. rray_slice() handles axis 1 with one tight loop over each whole output column, so it avoids it.

Character and list data: the two approaches tie within 7%. R's cost of writing each string dominates either way.

r_obj* rray_rep(
  r_obj* x,
  r_obj* times,
  r_obj* axes,
  struct rray_arg* x_arg,
  struct r_lazy error_call
) {
  check_unclassed(x, x_arg, error_call);
  x = KEEP(arg_as_array(x, x_arg, error_call));

  r_obj* x_dimensions = r_dim(x);
  const int* v_x_dimensions = r_int_cbegin(x_dimensions);
  const int dimensionality = rray_dimensionality_from_dimensions(x_dimensions);
  check_dimensionality(dimensionality);

  axes = KEEP(arg_as_axes(axes, dimensionality, rray_args.axes, error_call));
  const int* v_axes = r_int_cbegin(axes);
  const r_ssize axes_size = r_length(axes);

  times = KEEP(arg_as_rep_times(times, axes_size, rray_args.times, error_call));
  const int* v_times = r_int_cbegin(times);
  const r_ssize times_size = r_length(times);

  int v_out_dimensions[RRAY_MAX_DIMENSIONALITY];
  r_memcpy(v_out_dimensions, v_x_dimensions, sizeof(int) * dimensionality);

  for (r_ssize i = 0; i < axes_size; ++i) {
    const int axis = v_axes[i];
    const int times = v_times[times_size == 1 ? 0 : i];
    v_out_dimensions[axis - 1] =
      rray_rep_dimension(v_x_dimensions[axis - 1], times, error_call);
  }

  rray_size_from_dimensions_checked(
    v_out_dimensions,
    dimensionality,
    error_call
  );

  r_obj* indices = KEEP(r_alloc_list(dimensionality));

  for (int i = 0; i < dimensionality; ++i) {
    r_list_poke(indices, i, r_true);
  }

  for (r_ssize i = 0; i < axes_size; ++i) {
    const int axis = v_axes[i];
    const int times = v_times[times_size == 1 ? 0 : i];
    r_list_poke(
      indices,
      axis - 1,
      rray_rep_locations(v_x_dimensions[axis - 1], times)
    );
  }

  r_obj* out = rray_slice(x, indices, x_arg, rray_args.empty, error_call);

  FREE(4);
  return out;
}

static r_obj* arg_as_rep_times(
  r_obj* times,
  r_ssize axes_size,
  struct rray_arg* arg,
  struct r_lazy error_call
) {
  times = KEEP(arg_as_non_negative_bare_integer(times, arg, error_call));

  const r_ssize times_size = r_length(times);

  if (times_size != 1 && times_size != axes_size) {
    stop_rep_times_size(times_size, axes_size, arg, error_call);
  }

  FREE(1);
  return times;
}

static r_no_return void stop_rep_times_size(
  r_ssize times_size,
  r_ssize axes_size,
  struct rray_arg* arg,
  struct r_lazy error_call
) {
  if (axes_size == 1) {
    r_abort_lazy_call(
      error_call,
      "%s must be size 1, not size %" R_PRI_SSIZE ".",
      rray_arg_format(arg),
      times_size
    );
  } else {
    r_abort_lazy_call(
      error_call,
      "%s must be size 1 or size %" R_PRI_SSIZE " to match `axes`, "
      "not size %" R_PRI_SSIZE ".",
      rray_arg_format(arg),
      axes_size,
      times_size
    );
  }
}

  int times,
  struct r_lazy error_call
) {

    stop_rep_dimension_too_large(error_call);

static r_obj* rray_rep_locations(int dimension, int times) {
  r_obj* out = KEEP(r_alloc_integer(dimension * times));
  int* v_out = r_int_begin(out);

Yes on the first part. On the second, the missing TRUE shortcut isn't what makes it expensive.

Why it can't be a slice: a slice picks positions on each axis independently. Every output element combines one location from each axis's list, so every lane along an axis uses the same locations. rray_roll_each() breaks that: a lane's source positions along axis depend on that lane's own n. With a matrix and axis = 2, row 1 might read columns c(3, 1, 2) while row 2 reads c(2, 3, 1). No single location vector per axis can say that, so it has to be rray_index(), where every output element gets its own coordinates.

What it would cost with rray_index():

  • Other axes are cheap even without TRUE. Broadcasting already gives you most of what TRUE would. Each untouched axis can be seq_len(d) shaped with 1s on every other axis, for example array(1:d, c(1, d, 1)). That's only d integers each, and they broadcast.

  • The rolled axis is the real cost. Its coordinates depend on both the position along axis and the lane's n, so that coordinate array has to be as large as x itself. That means a full-size integer array allocated, then checked element by element. Today's fill reads n once per lane and allocates nothing extra.

  • Names would need rebuilding. rray_index() drops all names, but rray_roll_each() keeps names on every axis except axis. We would have to put those back ourselves.

So the missing fast path on rray_index() only saves small arrays. The unavoidable cost is the full-size coordinate array for the rolled axis. The trade that worked for rep, where location vectors are sized per axis, doesn't exist for rray_roll_each(), and its dedicated fill is worth keeping.
