#' Combine arrays along an existing axis
#'
#' `rray_combine()` joins one or more arrays along `.axis`. Dimensions on every
#' other axis are broadcast to common dimensions.
#'
#' @param ... Arrays to combine.
#'
#' @param .axis A single integer between 1 and the greatest input
#'   dimensionality.
#'
#' @returns
#' An array with the following dimensions:
#' - Along `.axis`, the input dimensions are added together.
#' - Along all other axes, the common dimensions are taken via broadcasting.
#'
#' @export
#' @examples
#' x <- array(1:6, c(2, 3))
#' y <- array(7:12, c(2, 3))
#'
#' rray_combine(x, y, .axis = 1)
#' rray_combine(x, y, .axis = 2)
#'
#' # Missing trailing axes have an implicit dimension of 1
#' rray_combine(1:2, array(3:8, c(2, 3)), .axis = 2)
rray_combine <- function(..., .axis) {
  .Call(ffi_rray_combine, list2(...), .axis, environment())
}

benchmark_pair <- function(group, case, rray4, comparison, other) {
  rray4()
  other()
  gc()

  result <- bench::mark(
    rray4 = rray4(),
    comparison = other(),
    iterations = iterations,
    check = TRUE,
    memory = TRUE
  )

  data.frame(
    group = group,
    case = case,
    implementation = c("rray4", comparison),
    median_ms = as.numeric(result$median) * 1000,
    mem_alloc_mb = as.numeric(result$mem_alloc) / 1024^2,
    relative_time = as.numeric(result$median) / min(as.numeric(result$median)),
    row.names = NULL
  )
}

benchmark_case <- function(group, case, implementations) {
  expected <- implementations[[1L]]()

  for (name in names(implementations)) {
    if (!equivalent(expected, implementations[[name]]())) {
      stop(
        sprintf("`%s` disagrees for case `%s / %s`.", name, group, case),
        call. = FALSE
      )
    }
  }

  gc()

  results <- lapply(implementations, function(implementation) {
    bench::mark(
      implementation(),
      iterations = iterations,
      check = FALSE,
      memory = TRUE,
      filter_gc = FALSE

  check_max_dimensionality(out_dimensionality);

    KEEP(rray_dimensions_common_opts(xs, &axis, 1, arg, error_call));

What it says

rray_combine() and broadcast::bind_array() are effectively tied everywhere, within noise. Both allocate exactly one result (15.26 MB); abind allocates 4x that on axis 1 and is 3-14x slower across the board. abind never wins a case.

Against base, rray_combine() is 2x faster than rbind() and ties cbind(). That gap is the expected one: cbind() on axis 2 is a straight memcpy, rbind() has to stride.

Dimnames are nearly free for rray_combine() (1.58 → 1.68 ms) and expensive for abind (18.06 → 23.44 ms).

The one bad case

At 1000 one-element inputs, rray_combine() takes 4.1 ms against rbind()'s 0.13 ms. None of that is your C code. It is rlang::list2(), which is quadratic in the number of dots:

n=  100  list()=  7.6us  list2()=    55.7us
n= 1000  list()= 80.2us  list2()=  3980.8us
n= 2000  list()=156.9us  list2()= 34056.1us

At n=1000 the whole rray_combine() call is 4.10 ms and function(...) list2(...) alone is 3.98 ms, so ~97% of the time is dots collection. rlang 1.3.0. rray_dimensions_common() and rray_broadcast_common() have the same ceiling since they collect dots the same way.

Two notes: I installed abind (it wasn't present). broadcast::bind_array() is also 4.08 ms on that case despite taking a plain list, so it has a separate per-input cost of its own.
