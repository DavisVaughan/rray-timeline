No, switching to bool_bitwise_or() does not help rray_and_lgl_one() or rray_or_lgl_one(). With the current ||, clang -O2 (what R CMD INSTALL uses here) already compiles both into branch-free vector loops.

Your question. I compiled logical.c and reduce-logical.c twice: once as on HEAD, and once with bool_bitwise_or(!x, !y) and bool_bitwise_or(x == 1, y == 1).

  • Both versions are the same length and have the same number of branches and vector instructions.

  • The only differences are equivalent single-cycle swaps. For example, cmtst + and becomes cmeq #0 + orr. That is the compiler flipping "both nonzero" into "neither is zero", which is the same logic.

  • The two operands are plain comparisons with no side effects, so the compiler is free to evaluate both. It drops the short circuit by itself.

xor and the pmax helpers likely benefited because their | sits inside a ?: choosing between two values. Here the bool feeds straight into arithmetic. I did not run timings for this variant, since the instruction counts already match. I can if you want numbers.

The benchmark of the na_rm rewrite. It changed nothing measurable.

  • What I compared: origin/main against the first commit on this branch, alternating over 3 rounds.

  • Data: 1e6 elements in 3 shapes. There were 5 data patterns: all TRUE, all FALSE, mixed, 10% NA and 90% NA.

  • Results: all outputs were identical between the two builds. The na_rm=TRUE cases had a geometric mean ratio of 0.999, and no single case moved by more than 3%. The na_rm=FALSE control cases ranged from 0.96 to 1.03, so the na_rm=TRUE spread is just noise.

So the rewrite is a readability change, not a speedup. The old x && y and (x == 1) || (y == 1) were already compiled branch-free as well.

One unrelated thing stood out. Reducing along axis 1 is about 10x slower than along the last axis: 844 µs for axis 1 against 79 µs for axis 2 on a 1000x1000 array. That cost is the same in both builds, so it comes from the reduction loop rather than these helpers. It may be worth a look later.
