Yes, it's doable, and it should be at least as fast as what we have now. Nothing gets slower. We just stop writing an 8-byte offset for every element and then reading it back.

Why performance holds

Today, extracting with double positions takes three passes and two temporary allocations:

  1. rray_as_extract_integer() converts the doubles into a new integer vector.

  2. rray_extract_positions_offsets() turns those into a raw buffer of r_ssize offsets.

  3. The gather loop reads the offsets and copies from x.

With your approach, as_subscript only checks the values and allocates nothing. The gather loop then reads i directly. We switch on the subscript kind once, outside the loop, so every loop body is specialized and the compiler can inline the offset math. Converting a double to an offset is an isnan() check and a cast, which costs next to nothing compared with the random reads from x.

Sketch

as_subscript returns a small struct instead of an r_obj*:

enum rray_subscript_kind {
  RRAY_SUBSCRIPT_positions_int,
  RRAY_SUBSCRIPT_positions_dbl,
  RRAY_SUBSCRIPT_mask,
  RRAY_SUBSCRIPT_points_int,
  RRAY_SUBSCRIPT_points_dbl
};

struct rray_subscript {
  r_obj* i;
  enum rray_subscript_kind kind;
  r_ssize size;
};

size is the number of selected elements. Validation already walks i, so counting there is free. Assign needs this count too, to check the size of value.

The offset getters are static inline functions in extract-subscript.h, so assign can reuse them:

static inline r_ssize rray_position_dbl_offset(const double* v_i, r_ssize j) {
  const double elt = v_i[j];
  return isnan(elt) ? -1 : (r_ssize) elt - 1;
}

The loop is then your GET_ONE idea, written as a macro:

for (r_ssize j = 0; j < size; ++j) {
  const r_ssize offset = OFFSET(v_i, j, __VA_ARGS__);
  v_out[j] = offset < 0 ? MISSING : v_x[offset];
}

For points, the extra arguments are size, v_strides, and dimensionality.

Where it doesn't fit cleanly

  • Masks: these don't have the v_out[j] = f(j) shape. A mask filters over x, so it needs its own loop: walk x and write v_out[k++] on each TRUE. That's still one pass with no allocation.

  • Negative positions: these still allocate the complement mask, which is the size of x. I don't see a cheap way around that, and negatives are the less common case.

  • Zero positions: I'd keep the compaction that drops zeros. It only allocates when a zero is present, and it keeps the positions loop in the simple v_out[j] shape. The other option is to skip zeros inside the loop, but then every positions extract pays for an extra branch.

  • Code size: 7 types of x times 5 subscript kinds gives 35 loops. Each rray_extract_{type}() becomes a 5-case switch over one macro, so it stays readable.

Side effects

  • vec_bare() goes away. We never return i to R, so its attributes don't matter.

  • Double positions no longer need the INT_MAX check. The real limit is the size of x, so arrays with more than INT_MAX elements get double positions for free.

  • The rray_as_extract_subscript() test helper changes shape, because there is no converted vector to return anymore. It could return list(i, kind, size). The tests "converts double positions to integer" and "drops attributes" would become tests of the kind and the count.

Decision for you

Should as_subscript return the struct, or keep returning r_obj* and leave extract to work out the kind from typeof and dim like it does now? I recommend the struct. Assign will need the kind and the count too, and this way that logic lives in one place.

Let me know which you prefer and I'll implement it.

Yes. as_subscript still owns both, so extract and assign never see a negative or a zero.

  • Negative positions: turned into the complement mask, and the kind becomes RRAY_SUBSCRIPT_mask.

  • Zero positions: compacted away, and the kind stays positions. Since we no longer convert doubles to integers first, compaction keeps the input type: double in, double out. That way it doesn't need a separate path.

These two cases are the only allocations left in the subscript step. They only happen when a negative or a zero is actually present. Plain positive positions, masks, and points pass through with no allocation.

  r_obj* x,
  r_obj* i,
  struct rray_arg* x_arg,
  struct rray_arg* i_arg,
  struct r_lazy error_call
) {
  check_unclassed(x, x_arg, error_call);
  x = KEEP(arg_as_array(x, x_arg, error_call));

  r_obj* dimensions = r_dim(x);
  const int* v_dimensions = r_int_cbegin(dimensions);
  const int dimensionality = rray_dimensionality_from_dimensions(dimensions);
  check_dimensionality(dimensionality);

  const struct rray_extract_subscript subscript = rray_as_extract_subscript(
    i,
    v_dimensions,
    dimensionality,
    i_arg,
    error_call
  );

    out = rray_extract_lgl(x, subscript, v_strides, dimensionality);

  case R_TYPE_integer:
    out = rray_extract_int(x, subscript, v_strides, dimensionality);
    break;
  case R_TYPE_double:
    out = rray_extract_dbl(x, subscript, v_strides, dimensionality);

  case R_TYPE_complex:
    out = rray_extract_cpl(x, subscript, v_strides, dimensionality);
    break;

    break;
  case R_TYPE_list:

    break;

static inline r_ssize rray_point_offset_int(
  const int* v_point,
  r_ssize size,
  const r_ssize* v_strides,
  int dimensionality
) {
  r_ssize out = 0;

  for (int axis = 0; axis < dimensionality; ++axis) {
    const int coordinate = v_point[axis * size];

    if (coordinate == r_globals.na_int) {
      return -1;
    }

    out += (r_ssize) (coordinate - 1) * v_strides[axis];
  }

  return out;
}

static inline r_ssize rray_point_offset_dbl(
  const double* v_point,
  r_ssize size,
  const r_ssize* v_strides,
  int dimensionality
) {
  r_ssize out = 0;

  for (int axis = 0; axis < dimensionality; ++axis) {
    const double coordinate = v_point[axis * size];

    if (isnan(coordinate)) {
      return -1;
    }

    out += ((r_ssize) coordinate - 1) * v_strides[axis];
  }

  return out;
}

    rray_subscript_summarise(i, 0, i_size);

    stop_subscript_fractional(i_arg, error_call);
  }
  if (summary.max > size) {
    r_abort_lazy_call(
      error_call,
      "%s must not contain values greater than %" R_PRI_SSIZE ".",
      rray_arg_format(i_arg),
      size

  }
  if (summary.min < -size) {

      error_call,
      "%s must not contain values less than -%" R_PRI_SSIZE ".",
      rray_arg_format(i_arg),
      size
    );
  }

  const bool any_negative = summary.min < 0;

  if (any_negative && summary.max > 0) {
    r_abort_lazy_call(
      error_call,
      "%s can't mix positive and negative values.",
      rray_arg_format(i_arg)
    );
  }
  if (any_negative && summary.any_missing) {
    r_abort_lazy_call(
      error_call,
      "%s can't mix negative and missing values.",
      rray_arg_format(i_arg)

Design

rray_as_extract_subscript() now returns this:

struct rray_extract_subscript {
  r_obj* i;
  enum rray_extract_subscript_kind kind;
  r_ssize size;
};

kind is one of positions_int, positions_dbl, mask, points_int, or points_dbl.

Validation (src/extract-subscript.c): it checks values but never converts them. One small pass per type (rray_subscript_summarise_int() or _dbl()) records the min, the max, the number of zeros, and whether anything is missing or fractional. Every position and point check reads from that summary, so the int and double paths share all the error logic. Negatives still become a complement mask, and zeros are still dropped. Dropping zeros keeps the input type.

Extract (src/extract.c): this uses the same POKE / ITERATE / ATOMIC / BARRIER macro shape as src/index.c. RRAY_EXTRACT_ITERATE() switches on the kind once, outside the loop. Each case runs a specialized loop that calls a small inline offset function, such as rray_position_offset_dbl() or rray_point_offset_int(). Masks have their own loop that walks x.

Protection

Helpers that allocate (the complement and zero-dropping paths) return subscript.i unprotected, just like a function returning r_obj*. Both callers call KEEP(subscript.i) right after the call returns. I also did the reading pass over every touched r_obj*, including names and out in the FFI wrapper and out in each per-type function. Nothing allocates while holding an unprotected value.

No. The compiler removes the multiply. I compiled the same loop with the flags R uses here (clang -O2, arm64), and this is what it produced:

lsl  x9, x1, #2       ; i_step * 4 bytes, once, before the loop
...
add  x0, x0, x9       ; inside the loop: bump the mask pointer

i_step doesn't change inside the loop, so clang turns v_i[location * i_step] into a pointer that moves forward by i_step each time. That's one add per element, the same cost as walking the mask with ++. GCC does the same thing at -O2.

The real cost in the mask loop is the two branches: elt == 0 and the NA check. With a random mask like x > 0.5 in the benchmark, the CPU guesses the elt == 0 branch wrong about half the time. That's why the mask case (about 4.5 ms) is slower than int positions (about 1.6 ms), even though it copies half as many elements.

A version without that branch would always write v_out[j] and then add elt != 0 to j. That would make random masks faster, but sparse masks might get slower because every element gets written. I haven't benchmarked it, so I'd leave it alone for now. I can try it if you want.
