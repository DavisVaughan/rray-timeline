Checking 5D fallback timing

Yes. I measured three performance weak spots:

Input Median time What costs time
Tiny 2×3 array, one element rray 2.1 µs; base R 0.4 µs Call and subscript setup dominate
One million element 1D array, TRUE rray 785 µs; base R 361 µs The slice loop copies element by element
One million element 1D array, half-TRUE logical mask rray 1.53 ms; base R 1.16 ms rray counts the mask, converts it to locations, then copies

There is also a 5-axis cost: adding a trailing axis of length one to the same million-element 4-axis slice raised rray’s median from 2.3 to 3.62 ms. The iterator has specialized paths through four axes and uses a general path above that.

These are benchmark medians from this machine, not guarantees for every workload. The existing slice benchmarks show rray ahead of base R on most other large cases they cover.
