Currently rray doesn’t support axis titles very well. We have an api for them but we don’t propagate them often

We still aren’t sure what names handling looks like in general for binary or more operations, so let’s leave those alone for now

But let’s create a detailed function by function plan in plans/titles.md that describes how each function that manipulates a single array could start propagating titles too. For example permute axes would have to rearrange them if present into axes order. Hopefully we can just add to existing names helpers to have them also handle titles in many cases.

Grill me on any questions or ambiguities rather than making guesses

r_obj* rray_set_titles(
  r_obj* x,
  r_obj* titles,
  struct rray_arg* arg,
  struct r_lazy error_call
) {
  check_unclassed(x, arg, error_call);
  x = KEEP(arg_as_array(x, arg, error_call));

  if (titles == r_null) {
    r_obj* out = rray_clear_titles(x);
    FREE(1);
    return out;
  }

  const int dimensionality = rray_dimensionality(x, arg, error_call);

  if (r_typeof(titles) != R_TYPE_character) {
    r_abort_lazy_call(
      error_call,
      "%s must be a character vector or `NULL`, not %s.",
      rray_arg_format(rray_args.titles),
      r_obj_type_friendly(titles)
    );
  }

  if (r_length(titles) != dimensionality) {
    r_abort_lazy_call(
      error_call,
      "%s must have length %d to match the dimensionality of %s, "
      "not length %" R_PRI_SSIZE ".",
      rray_arg_format(rray_args.titles),
      dimensionality,
      rray_arg_format(arg),
      r_length(titles)
    );
  }

  r_obj* old_names = r_dim_names(x);
  r_obj* new_names = KEEP(r_alloc_list(dimensionality));

  if (old_names != r_null) {
    r_obj* const* v_old_names = r_list_cbegin(old_names);
    for (int i = 0; i < dimensionality; ++i) {
      r_list_poke(new_names, i, v_old_names[i]);
    }
  }

  r_attrib_poke_names(new_names, titles);

  r_obj* out = KEEP(r_view(x));
  r_attrib_poke_dim(out, r_dim(x));
  r_attrib_poke_dim_names(out, new_names);

  FREE(3);
  return out;
}

// Create a read-only ALTREP view of an R object's data
//
// Useful when ONLY modifying the attributes of the new object, and NEVER the
// underlying data.
//
// The ALTREP view itself is immediately marked as immutable with
// `MARK_NOT_MUTABLE()`. This is extremely important! It ensures that R won't
// ever ask for a writable `DATAPTR()` without first calling `Duplicate()`.
//
// Note that R will VERY often use `REAL()` instead of `REAL_RO()` when it only
// needs a read-only pointer. This is due to `REAL_RO()` being a newer idea that
// was only introduced with ALTREP, and a lot of historical code hasn't been
// ported over. Because of that, our `DATAPTR()` ALTREP methods must return a
// pointer even in the `writable` case, but we expect that R (and all packages)
// hold up their side of the bargain by only actually writing to this pointer
// when they fully own it or when there are `NO_REFERENCES()`, which won't be
// the case since we've used `MARK_NOT_MUTABLE()`. The `NO_REFERENCES()` case is
// relevant for `x + y + 1` where R will attempt to reuse `x + y`'s temporary
// result since there aren't any other owners. We don't want
// `rray_set_dimensions(x) + 1` to look reusable!

  // If `x` is a view, take its original data and view that instead. This
  // avoids a proliferation of nested views. Refcounts on `x` itself should also
  // still be correct - each view looks like an individual user of `x`.
  r_obj* data = is_view(x) ? view_data(x) : x;

  // It now looks at least "referenced", but not necessarily "shared".
  r_obj* out = KEEP(R_new_altrep(cls, data, r_null));

  // The all important immutable marking of `out`, preventing any downstream C
  // code from requesting a writable pointer without duplicating first.
  MARK_NOT_MUTABLE(out);

  FREE(1);
  return out;

# Titles plan

## Goal

Every function that takes one array and returns one array should keep the
titles of `x` wherever its axes keep their meaning. Titles are the names on
the dimnames list:

```r
x <- array(1:24, c(2, 3, 4), dimnames = list(A = c("a", "b"), B = NULL, C = NULL))

rray_titles(x)
# [1] "A" "B" "C"
```

Binary and n-ary functions are out of scope until we settle how names combine
across inputs. See [Out of scope](#out-of-scope).

## Rules

These were decided up front and apply to every step.

- A title labels an axis, not its positions. An axis that keeps its identity
  keeps its title, even when it loses its names. `rray_sum(x, axes = 2)` keeps
  title `"B"` on axis 2.

- The result has a titles vector exactly when `x` has one. A new axis gets
  the title `""`. An all `""` titles vector is never turned into `NULL`. This
  matches `rray_set_axis_title(x, axis, NULL)`, which already leaves `""` in
  place.

- Titles can exist with no axis names at all. The dimnames list is then all
  `NULL` elements, like `list(A = NULL, B = NULL)`. Every helper must handle
  this case, which is the main trap: most names helpers only allocate their
  output list when some axis has names.

- A function that drops all names drops all titles. Today that is
  `rray_extract()`, `rray_index()`, and `rray_set_dimensions()`.

- `rray_set_names(x, names)` replaces the whole dimnames list. The names of
  `names` become the titles of `x`, so an unnamed list drops them and `NULL`
  clears everything.

- `rray_broadcast()` is left alone for now, see [Out of scope](#out-of-scope).

## Implementation pattern

Each step adds titles to an existing names helper rather than adding a new
code path. The pattern is the same everywhere:

1. Read `x_titles = r_names(x_names)` next to the existing `x_names`. It is
   protected through `x`.

2. If `x_titles != r_null`, allocate the output names list up front instead of
   lazily, so a titles-only input still gets a list.

3. Either reuse `x_titles` unchanged (when the result has the same axes as
   `x`) or build an `out_titles` character vector in the same loop that builds
   the output names (when axes move, appear, or disappear).

4. Poke the titles onto the output list with `r_attrib_poke_names()`.

`r_alloc_character()` fills with `""`, so new axes need no explicit poke.

Per the `AGENTS.md` protection review, `out_titles` is allocated while the
output list is live, so `KEEP()` it until it is poked onto the list.
