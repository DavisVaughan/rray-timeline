## Extract or Replace Parts of an Object

### Description

Operators acting on vectors, matrices, arrays and lists to extract or replace parts.

### Usage
    
    `x[i]
    x[i, j, ... , drop = TRUE]
    x[[i, exact = TRUE]]
    x[[i, j, ..., exact = TRUE]]
    x$name
    getElement(object, name)
    
    x[i] <- value
    x[i, j, ...] <- value
    x[[i]] <- value
    x$name <- value
    `

### Arguments

`x`, `object`  | object from which to extract element(s) or in which to replace element(s).
`i`, `j`, `...`  | indices specifying elements to extract or replace. Indices are `numeric` or `character` vectors or empty (missing) or `NULL`. Numeric values are coerced to integer or whole numbers as by `as.integer` or for large values by `trunc` (and hence truncated towards zero). Character vectors will be matched to the `names` of the object (or for matrices/arrays, the `dimnames`): see ‘Character indices’ below for further details. For `[`-indexing only: `i`, `j`, `...` can be logical vectors, indicating elements/slices to select. 
Indexing via a character matrix with one column per dimensions is also supported if the array has dimension names. As with numeric matrix indexing, each row of the index matrix selects a single element of the array. Indices are matched against the appropriate dimension names. `NA` is allowed and will produce an `NA` in the result. Unmatched indices as well as the empty string (`""`) are not allowed and will result in an error.

A vector obtained by matrix indexing will be unnamed unless `x` is one-dimensional when the row names (if any) will be indexed to provide names for the result.

### Recursive (list-like) objects

Indexing by `[` is similar to atomic vectors and selects a list of the specified element(s).

Both `[[` and `$` select a single element of the list. The main difference is that `$` does not allow computed indices, whereas `[[` does. `x$name` is equivalent to `x[["name", exact = FALSE]]`. Also, the partial matching behavior of `[[` can be controlled using the `exact` argument.

`getElement(x, name)` is a version of `x[[name, exact = TRUE]]` which for formally classed (S4) objects returns `slot(x, name)`, hence providing access to even more general list-like objects.

`[` and `[[` are sometimes applied to other recursive objects such as calls and expressions. Pairlists (such as calls) are coerced to lists for extraction by `[`, but all three operators can be used for replacement.

`[[` can be applied recursively to lists, so that if the single index `i` is a vector of length `p`, `alist[[i]]` is equivalent to `alist[[i1]]...[[ip]]` providing all but the final indexing results in a list.

Attempts to extract a non-existent element by name return `NULL`.

Note that in all three kinds of replacement, a value of `NULL` deletes the corresponding item of the list. To set entries to `NULL`, you need `x[i] <- list(NULL)`.

When `$<-` is applied to a `NULL` `x`, it first coerces `x` to `list()`. This is what also happens with `[[<-` where in R versions before 4.0.0, a length one value resulted in a length one (atomic) vector.

### Environments

Both `$` and `[[` can be applied to environments. Only character indices are allowed and no partial matching is done. The semantics of these operations are those of `get(i, env = x, inherits = FALSE)`. If no match is found then `NULL` is returned. The replacement versions, `$<-` and `[[<-`, can also be used. Again, only character arguments are allowed. The semantics in this case are those of `assign(i, value, env = x, inherits = FALSE)`. Such an assignment will either create a new binding or change the existing binding in `x`.

### NAs in indexing

When extracting, a numerical, logical or character `NA` index picks an unknown element and so returns `NA` in the corresponding element of a logical, integer, numeric, complex or character result, and `NULL` for a list. (It returns `00` for a raw result.)

When replacing (that is using indexing on the lhs of an assignment) `NA` does not select any element to be replaced. As there is ambiguity as to whether an element of the rhs should be used or not, this is only allowed if the rhs value is of length one (so the two interpretations would have the same outcome). --------------------------------------------------------------------------------

+# Allow missing indices in `rray_extract_assign()`
+
+## Goal
+
+Make `rray_extract_assign()` handle missing indices like
+`vctrs::vec_assign()`: a missing index uses a replacement slot but does not
+change `x`. Keep rray's existing forms of `i`, including full-array logical
+masks and matrices of coordinate points.
+
+```r
+x <- array(1:4)
+
+rray_extract_assign(x, c(1L, NA_integer_, 4L), c(10L, 20L, 30L))
+# array(c(10L, 2L, 3L, 30L))
+
+rray_extract_assign(x, c(TRUE, NA, FALSE, TRUE), c(10L, 20L, 30L))
+# array(c(10L, 2L, 3L, 30L))
+```
+
+The middle replacement value is unused in both calls. A single replacement
+value still broadcasts to every slot, including missing ones. This follows
+the location and replacement-size rules of
+[`vec_assign()`](https://vctrs.r-lib.org/reference/vec_slice.html) and
+[`vec_as_location()`](https://vctrs.r-lib.org/reference/vec_as_location.html).
+
+`vec_assign()` indexes the first dimension and does not accept an array as
+`i`. Rray keeps its own flat indexing and full-array mask rules. For a point
+matrix, skipping a row with a missing coordinate is the rray extension of
+the same missing-slot rule.
+
+## Contract
+
+| Form of `i` | Missing index | Replacement slots |
+|---|---|---|
+| Positive integer locations | `NA_integer_` skips the write | One per nonzero location, including `NA` |
+| Positive double locations | `NA_real_` and `NaN` skip the write | One per nonzero location, including missing values |
+| Logical vector or array | `NA` skips the write | One per `TRUE` or `NA` after scalar expansion |
+| Integer or double point matrix | A row with any missing coordinate skips the write | One per row, including missing rows |
+
+The replacement value must have size one or the number of replacement slots.
+It is cast to the type of `x` and checked for size before any writes. Missing
+slots are counted for this check even when every slot is missing. A value of
+size zero remains valid only when there are no slots. A mismatch remains an
+error even if skipping missing slots would leave the same number of actual
+writes as values.
+
+```r
+rray_extract_assign(array(1:4), c(1L, NA_integer_, 4L), c(10L, 30L))
+# Error: value has size 2, but the index has 3 slots
+```

+
+- Zero locations are removed before counting slots.

+  locations cannot be combined.

+  leaves `x` unchanged and has `rray_size(x)` replacement slots.
+- Logical arrays must still have the same dimensions as `x`.
+- Non-missing point coordinates must still be positive and in bounds. Validate
+  every coordinate column, including columns in a row that also contains a
+  missing coordinate.
+- Repeated non-missing locations still use the last corresponding replacement
+  value.

# Allow missing indices in `rray_extract_assign()`

## Goal

Make `rray_extract_assign()` handle missing indices like
`vctrs::vec_assign()`: a missing index uses a replacement slot but does not
change `x`. Keep rray's existing forms of `i`, including full-array logical
masks and matrices of coordinate points.

```r
x <- array(1:4)

identical(
  rray_extract_assign(x, c(1L, NA_integer_, 4L), c(10L, 20L, 30L)),
  array(c(10L, 2L, 3L, 30L))
)

identical(
  rray_extract_assign(x, c(TRUE, NA, FALSE, TRUE), c(10L, 20L, 30L)),
  array(c(10L, 2L, 3L, 30L))
)
```

The middle replacement value is unused in both calls. A single replacement
value still broadcasts to every slot, including missing ones. This follows
the location and replacement-size rules of
[`vec_assign()`](https://vctrs.r-lib.org/reference/vec_slice.html) and
[`vec_as_location()`](https://vctrs.r-lib.org/reference/vec_as_location.html).

`vec_assign()` indexes the first dimension and does not accept an array as
`i`. Rray keeps its own flat indexing and full-array mask rules. For a point
matrix, skipping a row with a missing coordinate is the rray extension of
the same missing-slot rule.

## Contract

| Form of `i` | Missing index | Replacement slots |
|---|---|---|
| Positive integer locations | `NA_integer_` skips the write | One per nonzero location, including `NA` |
| Positive double locations | `NA_real_` and `NaN` skip the write | One per nonzero location, including missing values |
| Logical vector or array | `NA` skips the write | One per `TRUE` or `NA` after scalar expansion |
| Integer or double point matrix | A row with any missing coordinate skips the write | One per row, including missing rows |

The replacement value must have size one or the number of replacement slots.
It is cast to the type of `x` and checked for size before any writes. Missing
slots are counted for this check even when every slot is missing. A value of
size zero remains valid only when there are no slots. A mismatch remains an
error even if skipping missing slots would leave the same number of actual
writes as values.

For example, assigning `c(10L, 30L)` through
`c(1L, NA_integer_, 4L)` is a size error: two values cannot fill three
slots.

Keep the other index rules:

- Zero locations are removed before counting slots.
- Negative locations still select the complement. Negative and missing
  locations cannot be combined.
- A scalar logical `NA` expands across every element of `x`. It therefore
  leaves `x` unchanged and has `rray_size(x)` replacement slots.
- Logical arrays must still have the same dimensions as `x`.
- Non-missing point coordinates must still be positive and in bounds. Validate
  every coordinate column, including columns in a row that also contains a
  missing coordinate.
- Repeated non-missing locations still use the last corresponding replacement
  value.
- `rray_extract()` continues to return missing output for missing indices.
  This change applies only to assignment.
