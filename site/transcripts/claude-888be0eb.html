R throws "non-conformable arrays" in one case only: both inputs have a dim attribute and the two dim vectors are not identical. That means the same length and the same value on every axis. There is no broadcasting and no recycling between two arrays.

The check is conformable() in src/include/Rinlinedfuns.h:771:

if ((n = length(x)) != length(y))
    return FALSE;
for (i = 0; i < n; i++)
    if (INTEGER(x)[i] != INTEGER(y)[i])
        return FALSE;

The same check guards arithmetic (arithmetic.c:599), comparison (relop.c:316) and logical operators (logic.c:93). It only runs when both sides are arrays. "Array" here means any object with a dim attribute, including 1D arrays.

Shapes that error

Checked in R:

matrix(1:6, 2) + matrix(1:6, 3)                   # 2x3 vs 3x2
array(1:6, c(2, 3)) + array(1:6, c(2, 3, 1))      # trailing 1 still differs
array(1, 1) + matrix(1, 1, 1)                     # 1 vs 1x1, both size 1
array(1:3, 3) + matrix(1:3, 3, 1)                 # 1D vs 3x1
matrix(integer(), 0, 2) + matrix(integer(), 0, 3) # 0x2 vs 0x3, both empty
matrix(1:6, 2) == matrix(1:6, 3)                  # comparison
matrix(TRUE, 2, 3) & matrix(TRUE, 3, 2)           # logical

Some things that might seem to help but don't:

  • Arrays with the same size still error.

  • Axes of dimension 1 still error.

  • Having a different number of axes errors, even if the extra axes are all 1.

  • Empty arrays are not exempt.

Shapes that never give this error

When only one side is an array, the conformable check never runs. Normal vector recycling applies instead, and other errors or warnings can come up:

matrix(1:6, 2) + 1:6        # ok
matrix(1:6, 2) + integer()  # ok, keeps the dims
matrix(1:6, 2) + 1:4        # warning: longer object length is not a multiple...
matrix(1:6, 2) + 1:7        # error: dims [product 6] do not match the length of object [7]
matrix(1, 1) + 1:3          # warning: Recycling array of length 1 ... is deprecated

The size 1 case is special in arithmetic only (arithmetic.c:573). A size 1 array next to a non-array whose length is not 1 loses its dim and gets a deprecation warning. This happens only when exactly one side is an array, so it never gets around the conformable check.

%*% and crossprod() have their own, different error, "non-conformable arguments" (array.c:1397). It is a matrix multiplication check on inner dimensions, not this one.
